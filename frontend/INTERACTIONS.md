# Как работает интерфейс

## Регистрация и вход

`register.html` — обычная HTML-форма с POST и CSRF-токеном; JavaScript не нужен.
Атрибут `name` у поля задаёт ключ в `request.POST`.

`pages.register` читает имя, email и роль в словарь `fields`, пароль — в отдельную
переменную. `**fields` переносит пары из словаря в JSON запроса; пароль добавляется
к нему только для отправки в Go. Django вызывает `POST /api/v1/register` через
существующий `get_json`. Go проверяет ввод и записывает аккаунт с хешем пароля.

При ошибке регистрации форма получает имя, email, роль и текст ошибки.
Пароль не возвращается в HTML. Повторный email получает понятное сообщение.

После успешной регистрации Django вызывает `POST /api/v1/login` с теми же
email и паролем. Если этот запрос не удался, открывается вход с пояснением,
что аккаунт уже создан. Повторного создания аккаунта нет.

При успешном входе `rotate_token` меняет CSRF-токен; cookie `go_session` хранит
полученный от Go токен на устройстве пользователя. HttpOnly запрещает чтение cookie
из JavaScript, SameSite=Lax ограничивает передачу между сайтами. Secure включается
через `COOKIE_SECURE=true`. Cookie действует 24 часа; сессия Go хранится в памяти,
поэтому после перезапуска Go нужно войти заново.

Роль из ответа Go выбирает адрес кабинета. Отдельных классов форм или новых
обёрток авторизации нет. Несколько строк установки cookie оставлены непосредственно
в регистрации и входе, чтобы оба обработчика можно было прочитать целиком.

## Рабочие разделы

Ученики, группы и банк используют Go API. Фильтры передаются через GET.
Изменения групп отправляются через POST формы Django в существующие методы Go.

`builder.js` управляет порядком выбранных задач. Сохранение черновика происходит
в `localStorage` браузера отдельно для пользователя. Записи варианта в БД через
эту кнопку нет. «Создать и опубликовать» отправляет вариант в Go; затем его можно
назначить ученику. Пароли и токены в localStorage не записываются.

## Неподключённые разделы

В `config/urls.py` пять адресов используют `not_connected`, передавая заголовок
и активный пункт меню. Это одна обычная функция вместо одинаковых обработчиков.
Она запрашивает свой профиль в Go; без сессии отправляет на вход.
Шаблон `not_connected.html` выбирает навигацию по роли из профиля и показывает
«Раздел пока не подключён». Параметры старых демонстрационных записей не используются.

Вымышленные расписание, работы и результаты удалены вместе с их шаблонами
и скриптами. Реальные данные PostgreSQL сохранены.

## Назначения, попытки и доска

Списки назначений и запуск попытки используют `learning_ui.py` и Go API.
`/solve/?attempt=<ID>` получает условия, ответы и ссылки на доски из Go.
Сохранение ответа и сдача проходят через POST Django с CSRF и проверку прав Go.
Доска использует WebSocket Go и cookie текущей сессии; после сдачи права
редактирования определяет Go. Сборка и запуск — [solve-board/README.md](solve-board/README.md).
