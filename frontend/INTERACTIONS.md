# Как работают функциональные элементы

Это демонстрационный frontend. Python читает готовые примеры из backend_client.py.
Авторизация, выставление итоговых оценок и другие правила платформы остаются задачей Go.
В интерфейсе нет отправки изменяющих запросов к Go и нет предметной БД Django.

## Поиск, фильтры, календарь и период статистики

Кнопки «Найти», «Показать» и вкладки работают через GET:

1. Браузер открывает адрес с параметрами, например `?q=Анна&status=attention`.
2. Python читает `request.GET`, выбирает демонстрационные записи и вызывает `render`.
3. Браузер получает новую HTML-страницу.

Поиск студентов, групп, работ и комментариев не меняет данные. Календарь переключает
`view=day/week/month`; поле дня передаёт `day`. Это демонстрационный ноябрь 2026 года,
а не настоящий календарный сервис. `event` открывает сведения о событии.
`period=30/90` меняет готовую выборку статистики. SVG-график строится из этих же
чисел, точные значения есть в таблице под ним. JavaScript здесь не используется.

## Проверка работ — static/review.js

- «Засчитать», «Частично», «Не засчитать» подставляют готовый пример балла в поле.
  Значения кнопок приходят из backend_client.py, а не вычисляются проверяющим алгоритмом JS.
- Балл можно изменить вручную. HTML ограничивает его диапазоном от 0 до максимума.
- «Предпросмотр результата» вызывает `reportValidity()` — браузер проверяет поле.
  Затем JS показывает введённый балл и комментарий. После редактирования старый
  предпросмотр скрывается.
- Результат не сохраняется и не публикуется. После перехода к другой работе ввод сбрасывается.

Объект `button.dataset` читает атрибуты HTML: `data-score="2"` становится
`button.dataset.score`. `textContent` вставляет обычный текст, не исполняя HTML.

## Конструктор — static/builder.js

Банк теперь поступает из Go через `db.ListTasks`: доступны фильтры предмета,
года, номера и типа. Показываются реальные условия и происхождение; ответы и
решения не выдаются. Баллы примерных заданий убраны. Серверное сохранение
варианта пока не подключено.


Данные передаются через `json_script`: Django записывает безопасный JSON-блок
в HTML. `JSON.parse` превращает его в объект JavaScript. Это уже загруженные
примеры, дополнительного сетевого запроса нет.

- «Добавить» дописывает ID задания в массив `selectedIds`. Массив — упорядоченный
  список. Повторное добавление того же ID запрещено интерфейсом.
- «Удалить» убирает ID через `splice`. «Выше» и «Ниже» меняют местами соседние ID.
- После изменения `renderSelectedTasks()` заново собирает видимый список через
  `document.createElement` и `textContent`. HTML не исполняется из названий заданий.
- Поиск банка скрывает строки, не содержащие введённый текст; всё происходит в браузере.
- «Сохранить черновик» записывает название и ID заданий в localStorage под ключом
  `go-edtech:builder:<userID>:v2`.
- При открытии страницы сохранённый черновик читается. Неизвестные ID игнорируются.
- «Сбросить черновик» удаляет только этот ключ и очищает состав варианта.

localStorage — постоянное хранилище данного браузера для адреса сайта. Оно не
привязано к аккаунту, не переносится между устройствами и может быть очищено браузером.
Если сохранение заблокировано, на странице появляется ошибка. Назначения работы пока нет.

## Решение варианта — static/solve.js

У каждого задания есть ID. Объект `answers` хранит пары «ID задания: текст ответа».

- Ввод текста меняет `answers` в памяти страницы. Это не автопроверка ответа.
- «Назад», «Далее» и номера заданий меняют `currentIndex` — номер показываемого задания.
  JS подставляет условие и ранее введённый ответ. «Ответ записан» означает только
  наличие непустого текста, а не правильность решения.
- «Сохранить черновик» записывает ответы и текущую позицию в localStorage. Ключ
  `go-edtech:answers:<ID варианта>:v1` разделяет черновики разных вариантов.
- При повторном открытии того же варианта JS восстанавливает этот черновик.
- «Завершить» открывает HTML-диалог через `showModal()` и показывает число заполненных ответов.
- «Продолжить решение» закрывает диалог через `close()`.
- «Посмотреть итог» закрывает диалог и показывает демонстрационный итог заполнения.
  Сдачи, выставления баллов и изменения состояния попытки на сервере не происходит.

Без нажатия «Сохранить черновик» свежие ответы потеряются при обновлении страницы.
Завершение не удаляет и не сохраняет черновик автоматически. Эталонные ответы в JSON
варианта не передаются. Время указано как условие примера; настоящего обратного
отсчёта нет. Доска и загрузка фотографий будут отдельными шагами.

## Регистрация — static/register.js

«Проверить данные» проверяет только форму в браузере:

1. Пустое имя отклоняется, в том числе если введены одни пробелы.
2. `reportValidity()` проверяет обязательные поля, формат email и минимум 8 символов пароля.
3. При корректном вводе показывается пояснение о демонстрации, поле пароля очищается.

У полей имени, email и пароля нет атрибута `name`, поэтому они не составляют
отправляемую HTML-формой запись. Кнопка имеет `type="button"`; JS также отменяет
событие submit через `preventDefault()`. POST на /register/ отклоняется Django.
Пароль не читается JS для отправки, не записывается в localStorage и не логируется.
Радиокнопка роли лишь выбирает значение формы: аккаунт, права и сеанс входа не создаются.
Настоящая регистрация потребует серверной проверки независимо от проверки браузера.

## Пока недоступные действия

«Пригласить», «Создать группу», «Перенести» и «Отменить» остаются явно недоступными.
В демонстрации они ничего не отправляют. Оплата в календаре — готовая подпись примера,
а не финансовая операция. Сообщений в приложении нет.

## Общие конструкции JavaScript

- `document.getElementById(...)` находит элемент страницы по ID.
- `addEventListener("click", ...)` задаёт действие при нажатии, `"input"` — при вводе.
- `const` объявляет переменную без последующего переназначения, `let` допускает переназначение.
- `JSON.stringify` превращает данные в текст для localStorage; `JSON.parse` читает его обратно.
- `try/catch` обрабатывает ошибку чтения или записи, чтобы показать понятное сообщение.
- `hidden` показывает/скрывает результат. `disabled` разрешает/запрещает действие.

Кнопки, зависящие от JS, включаются после загрузки своего скрипта. При его отсутствии
показывается пояснение noscript. Реальную доступность действия и его результат впоследствии
проверяет Go; изменение кнопки в браузере не заменяет серверную проверку прав.
