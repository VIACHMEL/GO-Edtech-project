# Django: заготовки страниц

Оформлены все 13 страниц: регистрация, 6 разделов преподавателя, 5 разделов
студента и решение варианта. `/` — навигация по прототипу. Общий тёмный каркас
содержит фиксированное меню и широкую рабочую область. Это готовность страниц
демонстрационного frontend, а не работающая платформа с реальными пользователями.
Все примеры данных находятся в `backend_client.py`; запросов к Go при
открытии страниц нет. Логика платформы остаётся на Go.

## Страницы

К адресу `http://127.0.0.1:8000` добавить путь из таблицы.
Например: `http://127.0.0.1:8000/teacher/students/`.

| Страница | Путь |
| --- | --- |
| Регистрация | `/register/` |
| Страница преподавателя | `/teacher/` |
| Студенты | `/teacher/students/` |
| Группы | `/teacher/groups/` |
| Проверка заданий и вариантов студентов | `/teacher/reviews/` |
| Конструктор вариантов | `/teacher/builder/` |
| Календарь + CRM преподавателя | `/teacher/calendar/` |
| Страница студента | `/student/` |
| Календарь + CRM студента | `/student/calendar/` |
| Задания и варианты | `/student/assignments/` |
| Комментарии преподавателя | `/student/comments/` |
| Статистика | `/student/statistics/` |
| Решение варианта | `/solve/` |

Это публичные заготовки без настоящих личных данных и действий.
Например, страница регистрации пока не регистрирует пользователя.
На странице решения варианта позже появится доска.
Сообщения исключены; старые адреса сообщений возвращают 404.

Там указано, что меняется в Python/JavaScript, где сохраняется черновик и какие
действия остаются только демонстрацией.

## Запуск

Из корня репозитория, Linux/macOS:

```sh
cd frontend
```

Если `.venv` ещё нет, создать её и установить зависимости:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

`.venv` — отдельная папка с Python и библиотеками этого проекта.
`requirements.txt` содержит Django и две необходимые ему библиотеки.
Повторять создание окружения при каждом запуске не нужно.

Проверить настройки, затем запустить локальный сервер:

```sh
.venv/bin/python manage.py check
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

Открыть http://127.0.0.1:8000/. Появится навигация по прототипу.
`127.0.0.1` — этот компьютер, `8000` — порт, на котором сервер принимает запросы.
Остановка сервера — Ctrl+C.

## Как проходит запрос

1. Браузер обращается к адресу `/`.
2. Django ищет этот адрес в `config/urls.py`.
3. Запись `path("", index)` выбирает функцию `index` из `pages.py`.
   Пустая строка обозначает корень `/`.
4. Django вызывает `index(request)`. `request` содержит сведения о пришедшем запросе.
5. `render(request, "index.html")` создаёт HTML-ответ из шаблона.

Страницы с данными сначала вызывают демонстрационные функции `backend_client.py`,
затем передают полученный словарь шаблону через `render`.
Завершающий слеш является частью адреса; используйте пути из таблицы.
Адреса, которых нет в списке правил, возвращают стандартную ошибку 404.

## Какие файлы участвуют

- `manage.py` передаёт команды установленному Django и указывает файл настроек.
- `config/settings.py` задаёт настройки.
- `config/urls.py` содержит адреса и первые три обработчика преподавателя.
- `pages.py` — остальные обработчики страниц: чтение GET, выбор записи и `render`.
- `config/__init__.py` — пустой файл, обозначающий пакет Python.
- `config/wsgi.py` соединяет Django с сервером при текущем запуске.
- `config/asgi.py` — альтернативный способ подключения; на этом шаге не используется.
- `backend_client.py` — демонстрационный ответ для главной и ранее написанный GET-клиент Go.
- `templates/workspace_base.html` — общий каркас кабинетов и профиль.
- `templates/teacher_base.html`, `templates/student_base.html` — меню двух кабинетов.
- `templates/teacher.html` — содержимое обзора.
- `templates/teacher_students.html`, `templates/teacher_groups.html` — списки и панели подробностей.
- `test_teacher_pages.py` — проверки поиска, фильтров, панелей и обработки неверных параметров.
- `test_all_pages.py` — остальные страницы, календарь, данные для JS, регистрация и ошибки.
- `static/styles.css` — оформление страницы и расположение областей на разных экранах.
- `static/builder.js`, `review.js`, `solve.js`, `register.js` — локальные действия в браузере.

## Каждая настройка

- `SECRET_KEY` — служебный ключ Django. Генерируется заново при запуске; постоянных сеансов здесь нет.
- `DEBUG = True` — подробные сообщения об ошибках для разработки.
- `ALLOWED_HOSTS` — разрешённые имена компьютера в обращениях к серверу.
- `ROOT_URLCONF` — где Django ищет соответствие адресов функциям.
- `WSGI_APPLICATION` — какую функцию подключения к серверу использовать.
- `BASE_DIR` — путь к frontend/. `Path(__file__).resolve().parent.parent` берёт путь
  файла настроек и поднимается на две папки вверх. `Path` — средство Python для работы с путями.
- `INSTALLED_APPS` — подключено только встроенное `django.contrib.staticfiles`,
  которое помогает Django находить и отдавать CSS при локальной разработке.
- `MIDDLEWARE = []` — дополнительные промежуточные обработчики запросов не подключены.
- `DATABASES = {}` — база данных не подключена.
- `BACKEND_BASE_URL` — адрес будущего Go-сервера, сейчас `http://127.0.0.1:8080`.
- `BACKEND_TIMEOUT` — время ожидания сетевой операции в секундах, сейчас 3.
- `TEMPLATES` — список настроек шаблонов. `BACKEND` здесь означает движок шаблонов
  Django, а не Go. `DIRS` указывает на `frontend/templates/`; `APP_DIRS = False`
  означает, что искать шаблоны внутри дополнительных приложений не нужно.
- `STATIC_URL` — начало адресов файлов оформления: `/static/`.
- `STATICFILES_DIRS` — папка, где лежит CSS.
- `STATIC_ROOT` — папка для копий статических файлов после `collectstatic`.

Здесь нет чтения `.env`, переадресаций и настоящего входа.
Старые описания других возможностей в документах вне frontend/ относятся к удалённой
заготовке, а не к текущему коду.
Настройки предназначены только для локального запуска.

## Главная преподавателя: как работают Python и шаблон

В `backend_client.py` появилась функция `get_teacher_overview()`. Она каждый раз
возвращает новый словарь Python с вымышленными данными. Это симуляция уже разобранного
ответа сервера: без сети и авторизации. Все имена, время, даты, количества и статусы
из примера записаны там. Демонстрационный день — 3 ноября 2026 года; он не меняется
по часам компьютера.

Основные ключи ответа:

| Ключ | Что содержит |
| --- | --- |
| `teacher` | Имя, инициалы и предмет преподавателя |
| `date`, `date_detail` | Подписи демонстрационного дня |
| `next_lesson` | Следующее занятие |
| `lessons` | Список занятий на день |
| `attention` | Количество и описание задач, требующих внимания |

Словарь хранит пары «имя: значение», список — последовательность элементов.
Например, `overview["teacher"]["name"]` получает имя, а `overview["lessons"][0]`
получает первое занятие.
`is_next` и `is_finished` — подготовленные значения True/False, а не расчёт статуса в Django.

Функция страницы в `config/urls.py`:

```python
def teacher(request):
    overview = get_teacher_overview()
    return render(request, "teacher.html", {
        "overview": overview,
        "profile": overview["teacher"],
        "page_title": "Обзор",
        "active_page": "overview",
    })
```

1. Django вызывает `teacher`, когда браузер открывает `/teacher/`.
2. `get_teacher_overview()` возвращает демонстрационные данные.
3. `render` получает входящий запрос, имя шаблона и словарь переменных для него.
4. Ключ `"overview"` задаёт имя данных в шаблоне. `profile` передаёт профиль в общий
   каркас, `page_title` — название раздела, `active_page` — выбранный пункт меню.
5. Django подставляет данные в HTML и возвращает готовую страницу браузеру.

Основные записи в шаблоне:

- `{{ overview.teacher.name }}` — вывести имя. В шаблонах Django точками можно обращаться к ключам словаря.
- `{% for lesson in overview.lessons %}` — повторить разметку для каждого занятия.
- `{% empty %}` — показать текст, если список пустой.
- `{% if overview.next_lesson %}` — показать занятие, если оно есть; иначе — пустое состояние.
- `{% load static %}` и `{% static 'styles.css' %}` — подключить средства поиска CSS и получить его адрес.

Текст из данных автоматически экранируется Django: например, `<` отображается
как символ, а не начало HTML-тега. Отключать это поведение для данных не нужно.

переходят под описание средствами CSS.

## Студенты и группы

### Общий каркас

`workspace_base.html` содержит профиль, подключение CSS и места для меню и содержимого.
`teacher_base.html` заполняет блок меню преподавателя. Страницы наследуют его через
`{% extends "teacher_base.html" %}` и заполняют `{% block content %}`. У студента
аналогичное меню в `student_base.html`. Наследование шаблонов не даёт прав доступа.

### Демонстрационные данные

`get_demo_students()` возвращает новые записи вымышленных учеников,
`get_demo_groups()` — групп, `get_teacher_profile()` — профиль преподавателя.
Контакты с доменом `example.invalid` — примеры, не действующие адреса.
Состояния, проценты и оценки заданы в примерах, а не вычисляются Django как
правила оценивания. Изменение страниц и запросы поиска не сохраняют данные.

`get_teacher_students(query, status)` имитирует серверный поиск и фильтрацию:

1. Получает полный список примеров.
2. Для каждого ученика собирает строку из имени, предмета и группы.
3. `casefold()` приводит запрос и строку к виду для сравнения без учёта регистра.
4. Проверяет вхождение запроса и соответствие фильтру.
5. Возвращает подходящие записи и общие количества для вкладок.

`get_teacher_groups(query, status)` работает аналогично. Дополнительно собирает
участников по списку `member_ids`: у каждой записи ученика есть учебный `id`,
а группа хранит список этих ID. Количество участников соответствует списку.
Эти ID и форматы — внутренние примеры frontend, не принятый API Go.

### Кнопка «Найти» и фильтры

Обе страницы используют обычную HTML-форму с `method="get"`. Нажатие кнопки или
Enter открывает адрес вроде `/teacher/students/?q=Анна&status=attention`.

- `request.GET.get("q", "")` читает запрос поиска; второе значение используется,
  если параметра нет. `strip()` убирает пробелы по краям.
- `request.GET.get("status", "all")` читает выбранный фильтр. Неизвестный фильтр
  заменяется на `all`.
- Функция страницы передаёт параметры в имитацию backend и затем в шаблон.
- Скрытое поле `status` сохраняет фильтр при новом поиске.
- Ссылки вкладок сохраняют поисковый запрос. Числа вкладок показывают количества
  во всём демонстрационном наборе, а подпись под таблицей — текущий результат.
- `urlencode(...)` превращает словарь параметров в корректную строку адреса,
  кодируя пробелы, кириллицу и специальные символы.

Поиск пока не идёт при каждом нажатии клавиши. JavaScript не используется.
Фильтрация живёт только внутри имитации backend; после интеграции её выполняет Go.

### Подробности

`?student=s1` или `?group=g1` выбирает запись. Python ищет её в текущем результате,
а шаблон добавляет боковую панель. Студент: контакты, ближайшее занятие, готовые
результаты, заметка и задания. Группа: расписание, участники, последние задания и заметка.

Параметры поиска сохраняются при открытии и закрытии панели. Поиск или смена
вкладки закрывают старую панель. Неизвестный ID или запись вне текущего результата
дают 404. Это не механизм авторизации: все записи вымышленные и публичные.
На узком экране панель размещается под таблицей, сама таблица прокручивается по горизонтали.

### Пока недоступно

«Пригласить» и «Создать группу» — недоступные кнопки с подписью. Они не отправляют
писем, не открывают формы и не изменяют данные. Обработка регистрации, приглашений
и создания групп будет отдельным шагом. Переносов страниц и прав из Go здесь нет.

## Базовый backend_client

Клиент — код, который обращается к другой программе. Оформленные страницы используют
имитации ответов `get_teacher_overview()`, `get_teacher_students()` и `get_teacher_groups()`.
Ранее написанная сетевая функция `get_json()`
сохранена для будущего подключения Go и сейчас страницами не вызывается.
Остальные страницы также используют демонстрационные функции этого файла:
банк заданий, очередь проверки, календарь, работы, комментарии, статистику и варианты.

Пример будущего сетевого вызова:

```python
from backend_client import get_json

data = get_json("/example/")
```

`/example/` — учебный путь, не существующая операция Go. Адреса и формат ответов
нужно согласовать с backend. Путь задаёт наш код, а не ввод пользователя.
Этот пример можно выполнить внутри `manage.py shell`, где Django уже загрузил настройки.
Без запущенного сервера по настроенному адресу обращение завершится ошибкой.

### От вызова к данным

1. `path` — путь операции, например `/example/`; он должен начинаться с одного `/`.
2. `settings` даёт доступ к настройкам Django.
3. `rstrip("/")` убирает завершающий слеш у базового адреса. Сложение строк даёт
   полный адрес, например `http://127.0.0.1:8080/example/`.
4. `Request(...)` создаёт объект — описание будущего запроса. Сеть пока не используется.
   Он содержит адрес, метод `GET` (получить данные) и заголовок `Accept` (желаемый формат).
5. `urlopen(...)` отправляет запрос и возвращает объект ответа. Время ожидания берётся
   из `BACKEND_TIMEOUT`; это ограничение сетевых операций, не всего выполнения функции.
6. `with ... as response` позволяет работать с ответом и автоматически закрывает его
   при выходе из блока, в том числе при ошибке чтения.
7. `response.read()` читает тело ответа как байты — последовательность чисел.
   Также у ответа доступны `response.status` (HTTP-статус) и `response.headers`
   (служебные поля ответа).
8. `body.decode("utf-8")` превращает байты в текст с поддержкой кириллицы.
9. `json.loads(text)` разбирает JSON — текстовый формат данных. Например,
   `{"message": "Привет"}` превращается в словарь Python, из которого значение
   можно получить через `data["message"]`. JSON-массив превращается в список Python.
10. `return data` возвращает вызывающему коду разобранные данные, а не объект ответа.

Входящий `request` в функции страницы и созданный здесь `Request(...)` — разные объекты:
первый описывает запрос браузера к Django, второй — исходящий запрос Django к Go.

### Ошибки

Функция пока оставляет стандартные ошибки Python. Они не заменяются пустыми данными.

| Ошибка | Значение |
| --- | --- |
| `ValueError` из проверки пути | Передан путь без одного начального `/` |
| `urllib.error.HTTPError` | Сервер ответил ошибочным HTTP-статусом, например 403 или 500; код доступен в `.code` |
| `urllib.error.URLError` | Не удалось установить соединение; причина доступна в `.reason` |
| `TimeoutError` | Превышено ожидание сетевой операции; при соединении может быть причиной внутри `URLError` |
| `UnicodeDecodeError` | Ответ не является корректным текстом UTF-8 |
| `json.JSONDecodeError` | Текст ответа не является корректным JSON |

Пример обработки двух случаев вызывающим кодом:

```python
from urllib.error import HTTPError, URLError
from backend_client import get_json

try:
    data = get_json("/example/")
except HTTPError as error:
    print("Сервер вернул HTTP-ошибку:", error.code)
    error.close()
except (URLError, TimeoutError):
    print("Не удалось получить ответ от сервера")
```

`try` обозначает действие, которое может завершиться ошибкой. `except` описывает,
что делать при указанном виде ошибки. `HTTPError` проверяется первым, потому что
он является частным случаем `URLError`. `error.close()` закрывает ответ с ошибкой.
Это пример для командной строки; обработку ошибок на страницах добавим отдельным шагом.

### Границы текущей версии

Только GET и непустой JSON в UTF-8. Нет входа, паролей, передачи файлов, POST,
автоматических повторов, проверки структуры данных и ограничения размера ответа.
Пустой ответ, в том числе HTTP 204, не получится разобрать как JSON.
Используется стандартное поведение urllib для HTTP-переадресаций и системных прокси.
Настоящие операции и авторизацию подключим после согласования с Go.

### Критерии готовности клиента

- [x] GET формируется с заголовком `Accept: application/json`.
- [x] JSON-ответ превращается в данные Python, включая русский текст.
- [x] Ответы 403/500, некорректный JSON, отсутствие соединения и тайм-аут различимы как ошибки.
- [x] Страницы продолжают работать без Go; новых библиотек не требуется.
