# Доска на странице решения

Доска встроена в Django-шаблон `/solve/`. React используется внутри панели Excalidraw. Условия, текстовый черновик и переходы между заданиями обслуживает существующий `solve.js`.

## Запуск

Нужны Node.js 20.19+ в ветке 20 или Node.js 22.12+, npm и установленные зависимости Django. Команды из корня репозитория:

```powershell
cd frontend/solve-board
npm ci
npm run build
cd ..
python manage.py runserver 127.0.0.1:8000
```

Сборка попадает в `frontend/static/solve-board/dist/`. Для развёртывания соберите доску перед `python manage.py collectstatic --noinput`. Текущий демонстрационный вариант на `/solve/` покажет сообщение о недоступной доске, пока Go не отдаёт данные для её подключения.

## Где что находится

| Файл | Что делает |
|---|---|
| `frontend/templates/solve.html` | Показывает задание, поле ответа и панель доски |
| `frontend/static/solve.js` | Передаёт выбранную позицию через событие `solve:task-changed`, ждёт сохранения при смене доски |
| `src/solve-board.js` | Получает выбранное задание и загружает редактор при наличии доски |
| `src/editor.jsx` | Подключает Excalidraw и показывает состояние соединения |
| `src/board-session.js` | Принимает снимки по WebSocket, отправляет правки и ждёт подтверждения |
| `src/scene.js` | Находит изменённые элементы и собирает рисунок из серверного состояния и ожидающих правок |

## Подключение к Go

В JSON страницы у каждого задания может быть объект `board` с полями `id` (положительное целое число) и `ws_path` (относительный путь на домене страницы). Django передаёт его из данных попытки. Два задания с одинаковым `id` и путём используют одну доску. Для первой части Go выдаёт один ID на попытку, для второй — отдельный ID на позицию. Режим редактирования задаёт сервер. После сдачи он присылает `can_edit: false`.

Ожидаемые форматы для реализации Go:

| Направление | Сообщение |
|---|---|
| Go → браузер | `{"seq":0,"can_edit":true,"elements":[]}` при подключении. Далее сервер присылает целиком актуальное состояние с номером последней применённой операции. |
| Браузер → Go | `{"op_id":"<UUID>","payload":{"elements":[…]}}`. Массив содержит изменённые элементы Excalidraw. Удалённый элемент передаётся с `isDeleted: true`. |
| Go → отправитель | Снимок с `ack_op_id` в ответ на принятую или повторно полученную операцию. При отказе возвращаются актуальный снимок, `ack_op_id` и поле `error`. |

Клиент отправляет одну операцию за раз и объединяет следующие правки по ID элемента. После разрыва соединения кнопка «Подключиться снова» загружает свежий снимок и повторяет неподтверждённую операцию с прежним UUID. Go должен распознавать повтор по `op_id` и возвращать актуальный снимок. Подтверждение отправляется после записи. Очередь хранится в открытой вкладке. Перезагрузка восстанавливает подтверждённый рисунок.

Идентификатор позиции для интеграции берётся из `worksheet_item_id` в ответе `GetAttemptAnswers`. Для определения части задания планируется использовать `metadata.exam_part` банка. Порядок задания внутри варианта может отличаться от номера в банке. Путь WebSocket, получение данных попытки, проверка сеанса и доступа к доске будут реализованы в Go. Формат опирается на номера операций и UUID из [проекта таблиц доски](../../docs/decisions/02-database-tables-and-fields.md#файлы-и-доска--ab). Сервис выполнения описан в [контракте вариантов и попыток](../../docs/contracts/worksheet-and-learning-contract.md#44-методы-service-ученик).
