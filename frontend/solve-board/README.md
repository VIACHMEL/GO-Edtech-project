# Доска на странице решения

Доска встроена в Django-шаблон `/solve/`. React используется внутри панели Excalidraw. Условия, текстовый черновик и переходы между заданиями обслуживает существующий `solve.js`.

## Запуск

Нужны Node.js 20.19+ в ветке 20 или Node.js 22.12+, npm и установленные зависимости Django. Команды из корня репозитория:

```powershell
cd frontend/solve-board
npm ci
npm run build
cd ..
python manage.py runserver 127.0.0.1:8000
```

Сборка попадает в `frontend/static/solve-board/dist/`. Соберите доску перед `python manage.py collectstatic --noinput`. Обычный `/solve/` открывает макет варианта. Для работы с базой откройте `/solve/?attempt=<ID>` через настроенный Go-сервер в сеансе ученика или преподавателя.

## Где что находится

| Файл | Что делает |
|---|---|
| `frontend/templates/solve.html` | Показывает задание, поле ответа и панель доски |
| `frontend/static/solve.js` | Передаёт выбранную позицию через событие `solve:task-changed`, ждёт сохранения при смене доски |
| `src/solve-board.js` | Получает выбранное задание и загружает редактор при наличии доски |
| `src/editor.jsx` | Подключает Excalidraw и показывает состояние соединения |
| `src/board-session.js` | Принимает снимки по WebSocket, отправляет правки и ждёт подтверждения |
| `src/scene.js` | Находит изменённые элементы и собирает рисунок из серверного состояния и ожидающих правок |

## Локальный запуск с PostgreSQL

Примените миграции `backend/internal/db/migrations` до `000010_boards` включительно к отдельной локальной базе. Для проверки нужны опубликованный вариант, назначение, открытая попытка и её ученик и преподаватель. В примере замените ID на записи из своей тестовой базы.

Запустите Django из `frontend`:

```powershell
$env:BACKEND_BASE_URL = 'http://127.0.0.1:8095'
python manage.py runserver 127.0.0.1:8096
```

В другом терминале из `backend` задайте `DATABASE_URL` и запустите Go:

```powershell
go run ./cmd/board-local -port 8095 -django-port 8096 -attempt 1 -student 2 -teacher 1
```

Go выведет две ссылки. Откройте их в разных профилях браузера: сеанс хранится в cookie. Идентификаторы записей проверяются по правилам доступа к попытке. Этот запуск слушает только loopback и предназначен для локальной базы. Для основного приложения регистрируйте `boardhttp.Register` с обработчиком действующей пользовательской сессии. Проксируйте `/ws/` и `/api/` в Go на том же домене, на котором работает Django. Django запрашивает данные попытки по `BACKEND_BASE_URL`.

## Подключение к Go

В JSON страницы у каждого задания может быть объект `board` с полями `id` (положительное целое число) и `ws_path` (относительный путь на домене страницы). Django передаёт его из данных попытки. Два задания с одинаковым `id` и путём используют одну доску. Для первой части Go выдаёт один ID на попытку, для второй — отдельный ID на позицию. Режим редактирования задаёт сервер. После сдачи он присылает `can_edit: false`.

`GET /api/attempts/{id}/solve` возвращает условия, текущие ответы и ссылки на доски. `PUT /api/attempts/{id}/answers/{item}` сохраняет текст через существующий механизм ревизий ответа. `POST /api/attempts/{id}/submit` сдаёт попытку. Канал `GET /ws/boards/{id}` требует сеанс и тот же Origin, что у страницы.

Формат WebSocket:

| Направление | Сообщение |
|---|---|
| Go → браузер | `{"seq":0,"can_edit":true,"elements":[]}` при подключении. Далее сервер присылает целиком актуальное состояние с номером последней применённой операции. |
| Браузер → Go | `{"op_id":"<UUID>","payload":{"elements":[…]}}`. Массив содержит изменённые элементы Excalidraw. Удалённый элемент передаётся с `isDeleted: true`. |
| Go → отправитель | Снимок с `ack_op_id` в ответ на принятую или повторно полученную операцию. При отказе возвращаются актуальный снимок, `ack_op_id` и поле `error`. |

Клиент отправляет одну операцию за раз и объединяет следующие правки по ID элемента. После разрыва соединения кнопка «Подключиться снова» загружает свежий снимок и повторяет неподтверждённую операцию с прежним UUID. Go должен распознавать повтор по `op_id` и возвращать актуальный снимок. Подтверждение отправляется после записи. Очередь хранится в открытой вкладке. Перезагрузка восстанавливает подтверждённый рисунок.

В `board_links` общая доска привязана к попытке, отдельная — к попытке и позиции того же варианта. Часть фиксируется при публикации из `metadata.exam_part`. Для математики ОГЭ без этого ключа Go берёт номер задания из банка: 1–19 — первая часть, 20–25 — вторая. При неизвестной части доска для позиции недоступна.

Go записывает операцию и актуальный снимок в одной транзакции. После записи он уведомляет открытые соединения в том же процессе. Проверка PostgreSQL раз в секунду подхватывает изменения из другого процесса и смену прав после сдачи или закрытия назначения. Каждый клиент видит снимок целиком. В этой версии лимит снимка — 512 КиБ, до 2000 элементов. Файл изображения не передаётся в снимке. Совместное изменение одного элемента сохраняется в порядке принятия сервером. Журнал операций пока хранится целиком.

Схема опирается на [проект таблиц доски](../../docs/decisions/02-database-tables-and-fields.md#файлы-и-доска--ab). Сервис выполнения описан в [контракте вариантов и попыток](../../docs/contracts/worksheet-and-learning-contract.md#44-методы-service-ученик).
