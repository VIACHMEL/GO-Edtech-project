# Доска на странице решения

Доска встроена в Django-страницу `/solve/?attempt=<ID>`. Excalidraw работает в браузере. Существующий Go-сервер проверяет сеанс, обслуживает WebSocket и сохраняет данные в PostgreSQL.

## Запуск

Примените миграции вплоть до `000013_task_conditions`. Соберите статические файлы доски. Нужны Node.js 20.19+ или 22.12+, npm и окружение Django.

Если локальная БД уже получила миграцию условий под старым номером
`000012_task_conditions`, колонка `task_versions.condition_html` в ней уже есть.
После резервной копии применяйте только отсутствующую `000012_board_sync`.
Прежний Go и новый протокол доски требуют разных схем. Для проверки без обновления
рабочей БД используйте отдельную базу с миграциями 000001–000013.

```powershell
cd frontend/solve-board
npm ci
npm run build
cd ..
python manage.py collectstatic --noinput
$env:GO_API_BASE_URL = 'http://127.0.0.1:8097'
python manage.py runserver 127.0.0.1:8098
```

В другом терминале из `backend` задайте `DATABASE_URL` и запустите Go.

```powershell
$env:BACKEND_ADDR = '127.0.0.1:8097'
$env:BOARD_ORIGIN = 'http://127.0.0.1:8097'
$env:DJANGO_PROXY_URL = 'http://127.0.0.1:8098'
go run ./cmd/server
```

Откройте [вход](http://127.0.0.1:8097/login/) в двух профилях браузера. У преподавателя создайте, опубликуйте и назначьте вариант связанному ученику. Ученик начинает попытку в разделе «Задания и варианты». Преподаватель открывает её из «Назначенные работы». Оба могут рисовать в одной попытке.

При публикации обновите Go и сборку доски вместе. Вкладки со старой версией нужно перезагрузить. На VPS прокси должен передавать WebSocket и запросы к файлам на том же домене, что и страницу. Установите `BOARD_ORIGIN` в публичный origin страницы. Действующие Go-сеансы хранятся в памяти процесса. После перезапуска сервера может потребоваться заново войти.

## Доступ и привязка

- Читать доску и изображения могут ученик этой попытки и назначивший работу преподаватель с активной связью с учеником. Права проверяет Go, используя существующий сеанс `go_session`.
- Правки принимаются в черновике активного назначения. После сдачи рисунки доступны для просмотра и экспорта.
- Повторная попытка получает новую доску. Групповая выдача создаёт отдельные назначения и доски для каждого ученика.
- Первая часть использует одну доску на попытку. Для каждого задания второй части создаётся отдельная доска. Часть фиксируется при публикации в `worksheet_items.exam_part_snapshot`.

## Контракт с парсером

| Поле в исходной задаче | Значение |
|---|---|
| `exam_type` | `oge` или `ege` |
| `subject`, `year`, `task_number` | Предмет, год и номер по спецификации экзамена |
| `metadata.exam_part` | Целое число `1` или `2` по спецификации этого предмета и года |

КЕГЭ записывает `exam_part` при импорте заданий ЕГЭ по информатике: №1–23 используют общую доску, №24–27 получают отдельные. Если у прежних задач поля нет, действует то же правило по номеру. Миграция `000013_task_conditions` заполняет пустые снимки опубликованных позиций этого экзамена и сохраняет явно заданные части. Для математики ОГЭ без `exam_part` действует правило 1–19 и 20–25. Если для другого предмета часть неизвестна, позиция открывается с условием и полем ответа.

## Протокол

`GET /api/v1/attempts/{id}/solve` возвращает `board: {id, ws_path}` у позиций с доской. Решения в текстовом поле и сдача идут через существующие методы попыток. Соединение `GET /ws/boards/{id}` требует сеанс и точный `Origin`.

| Направление | Сообщение |
|---|---|
| Клиент → Go | `{"op_id":"<UUID>","base_seq":12,"payload":{"elements":[…]}}`. Содержит изменённые элементы. Удаление передаётся как `isDeleted: true`. |
| Go → клиент | `type: "snapshot"` передаёт всю сцену. `type: "delta"` содержит изменённые элементы следующей ревизии. В обоих сообщениях есть `seq`, `can_edit` и `draft_owner`. |
| Go → автор | `ack_op_id` подтверждает запись или точный повтор операции. Отказ возвращает актуальный снимок с `error`. При `element_conflict` приходит список `conflicts`. |
| Go → клиент | `heartbeat` поддерживает неактивное соединение. `access_revoked` сообщает о потере доступа и закрывает его. |

В браузере правки объединяются каждые 100 мс и отправляются по одной операции. Если ответ не пришёл, клиент запрашивает актуальный снимок после переподключения и повторяет операцию с тем же UUID. Неотправленные изменения и ожидающая подтверждения операция сохраняются в `sessionStorage` по вкладке, доске и аккаунту. Черновик восстанавливается при перезагрузке той же вкладки. При проблемах с хранилищем редактор предупреждает о риске потери правок при закрытии. После перерыва между последовательными ревизиями клиент запрашивает снимок.

На сервере каждая правка применяется на основе указанной ревизии. Одновременные изменения разных объектов сохраняются. Если объект успел измениться после указанной ревизии, сервер отклоняет операцию целиком. Локальная правка остаётся в черновике. Применение поверх свежей версии требует подтверждения пользователя. Для операции старше доступной истории применяется та же процедура. Права на изменившуюся сцену проверяются перед её отправкой. Проверка метаданных каждые 3 секунды отслеживает сдачу и изменения из других процессов. Она читает ревизию и право записи. Полная сцена читается при подключении, пропуске ревизий и отправке актуального состояния после отказа.

## Изображения и экспорт

Кнопка «Изображение», вставка из буфера и перетаскивание принимают PNG и JPEG. Клиент временно хранит неподтверждённые файлы в IndexedDB. Перед отправкой элемента выполняется `PUT /api/v1/boards/{id}/files/{file_id}`. Остальные участники получают данные через `GET` того же маршрута. Элемент ссылается на ID файла той же доски. Повтор загрузки тех же байтов под тем же ID безопасен. SVG от пользователя не принимается.

Экспорт PNG и SVG выполняется в браузере. Изображения встраиваются в экспорт. Сохранить можно доступную сцену, в том числе локальные правки. Максимальная сторона PNG при экспорте составляет 4096 пикселей. В панели есть масштабирование, подгон по содержимому и полноэкранный режим. Редактор поддерживает касания. В браузере без полноэкранного API панель раскрывается на область окна.

## Хранение и лимиты

| Объект | Лимит или поведение |
|---|---|
| Снимок `boards.snapshot` и входящее WebSocket-сообщение | До 512 КиБ, до 2000 объектов в сцене |
| Журнал `board_operations` | 512 последних квитанций на доску. Хранятся UUID, автор, ревизия и хеш запроса. Старые записи удаляются при сохранении. |
| Ревизии удалённых объектов | До 4000 идентификаторов сверх активных объектов. Очистка поднимает нижнюю границу допустимой ревизии для правок. |
| PNG или JPEG | До 2 МиБ на файл, до 4096 пикселей на сторону и до 8 388 608 пикселей суммарно |
| `board_files` | До 64 файлов и 16 МиБ на доску. Файлы хранятся до удаления доски. |
| Соединения WebSocket | До 24 на доску, до 12 на пользователя в одной доске, до 256 на процесс |
| Операции WebSocket | До 100 за 10 секунд на одном соединении |

`board_links` связывает доску с попыткой и при необходимости с позицией. Снимок и квитанция записываются в одной транзакции. Изменения в одном Go-процессе передаются через локальные комнаты. Между процессами обновления подхватываются при проверке метаданных.

При откате миграции `000012` удаляются загруженные файлы и квитанции операций. Для их восстановления нужна резервная копия PostgreSQL.

## Проверки

```powershell
cd frontend/solve-board
npm test
npm run build
cd ../..
python frontend/solve-board/tests/board_browser.py
```

Браузерный тест требует Python Playwright 1.48+ и Chromium. Установленный Edge можно использовать через переменную `PLAYWRIGHT_CHANNEL=msedge`. Тест проверяет редактор на тестовых ответах API и WebSocket. Он покрывает загрузку изображений, перезагрузку с черновиком, синхронизацию, экспорт и управление на планшетном размере.

Для проверки Go создайте отдельную PostgreSQL с именем `edtech_test_db` или суффиксом `_test`, примените все миграции, задайте `EDTECH_TEST_DSN` и выполните из `backend`:

```powershell
go test -count=1 -v ./internal/boardhttp ./internal/db
go vet ./...
```

Тесты охватывают десять одновременных подключений к одной доске с правами двух участников, конфликт правок одного объекта, потерю сеанса, сохранение снимка и файлов между запусками, ограничения запросов и очистку журнала. Отдельно проверяются назначение группе из десяти учеников, изоляция досок и новая попытка после сдачи.
