# Go backend

Go 1.26, стандартный `net/http`, существующий PostgreSQL и готовые пакеты
`db`, `teacherdata`, `worksheetdata`, `learningdata`. Черновики конструктора сохраняются атомарно; редактор использует ревизии.

**Полное объяснение:** [docs/backend-explained.md](../docs/backend-explained.md).
Там схема запроса, синтаксис Go, все маршруты и тела JSON, полный цикл работы,
хранение сессий/фото и разбор каждой строки семи файлов `cmd/server`.

## Запуск

Подготовьте отдельную БД и примените существующие миграции 000001–000013 по порядку.
Уже применённые миграции повторно не запускать. Сервер сам миграции не применяет.

```sh
cd backend
export DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:15432/DB_NAME?sslmode=disable'
export BACKEND_ADDR='127.0.0.1:8080'
export UPLOAD_DIR='/absolute/path/outside/git/photos'
go run ./cmd/server
```

Адрес по умолчанию — `127.0.0.1:8080`, папка фото — `../data/uploads`
относительно рабочей папки. `.env` автоматически не загружается.
`GET /health` возвращает `{"status":"ok"}`; БД проверяется при запуске.

## Отбор и импорт заданий КЕГЭ

Команды выполняются из `backend/`. Задайте абсолютный `DATA_ROOT` для материалов.

- `go run ./cmd/kompege --select candidates.txt` принимает ID отдельных заданий.
- `go run ./cmd/kompege --select-variants kims.txt` принимает номера опубликованных КИМ из архива КЕГЭ. Оба списка читаются по одному числу на строку.
- Режимы отбора скачивают материалы выбранных задач без подключения к БД. Строки `SELECTED` содержат через табуляцию номер задания, ID и число материалов, строки `COVERAGE` — номер, число принятых и дефицит. Если кандидаты закончились раньше квоты или источник ограничил доступ, команда возвращает ошибку и печатает фактическое покрытие.
- Для записи укажите `DATABASE_URL` нужной БД и передайте проверенные ID, например `go run ./cmd/kompege 31500 31506`. Прежний режим `--range START END` также записывает задачи.
- Подзадания №20 и №21 в источнике идут внутри №19. Отбор обозначает их как `31516:20` и `31516:21`. Эти ссылки можно передать импорту.

В БД остаются URL источника и относительные пути артефактов от `DATA_ROOT`.
На диске файлы лежат в `kompege/<ID>/` под именами на основе SHA-256.
Go читает материалы из того же `DATA_ROOT`. Каталог и решалка отображают условия
с таблицами и изображениями, а ссылки на вложения выдаются после проверки доступа.

## Реализовано

- Регистрация teacher/student, вход, выход и изменение своего профиля.
- При входе логин без `@` дополняется до `<логин>@local.test`; email работает как прежде.
- Сессии в памяти Go на 24 часа; Django использует HttpOnly cookie.
- Приглашения, ученики, группы, состав и архивация групп.
- Банк без выдачи ответов/решений.
- Варианты, позиции, баллы, порядок, публикация, копирование и архив.
- Назначения ученику/группе, сроки, статусы, лимиты попыток и история.
- Ответы с ревизиями, сдача, автоматическая/ручная проверка и публикация результата.
- Приватные JPEG/PNG до 8 МиБ, связанные с ответом через существующий answer_data.

Django подключён к регистрации с автоматическим входом, входу, профилю, группам,
банку, конструктору, назначениям и попыткам. Вымышленные данные удалены;
неподключённые разделы показывают сообщение. Запуск совместной доски описан
в [инструкции](../frontend/solve-board/README.md). Парсер и SVG → TikZ —
отдельное направление MVP; этот HTTP-сервер не означает готовность всего MVP.

## Проверено

- `gofmt`, `go test ./...`, `go vet ./...`, сборка сервера.
- 84 HTTP-запроса к настоящему серверу на временной PostgreSQL: полный цикл
  двух учеников, права, ревизии, фото и отдельные результаты.
- Временная схема удалена, серверы остановлены. Сценарии после выполнения удалены
  по решению владельца; исходные тесты БД и парсера сохранены.
- Браузерная проверка недоступна в текущем окружении.

Сервер рассчитан на локальный запуск. Публичное размещение, ограничение частоты
входа, постоянные сессии, восстановление пароля и уборка сиротских файлов
не реализованы. Подробности и точные границы — в полном объяснении.

## Обновление хранения черновиков

Перед запуском этой версии на существующей БД примените `000011_worksheet_revision.up.sql`
после `000010`. Миграция добавляет `worksheets.revision` (старым строкам — 0) и триггер
увеличения ревизии при обновлении варианта, включая прежние методы редактирования.
`run.sh` применяет все миграции только к новой БД; существующую БД он не обновляет.
Остановите Go перед миграцией. Для отката сначала верните прежний Go-код, затем
примените down-миграцию 000011; варианты и позиции не удаляются.
Новых зависимостей нет. Постоянные сессии и очередь правок доски не изменены.
