# Go backend

Go 1.26, стандартный `net/http`, существующий PostgreSQL и готовые пакеты
`db`, `teacherdata`, `worksheetdata`, `learningdata`. Доска использует миграцию `000010` и авторизацию этого сервера.

**Полное объяснение:** [docs/backend-explained.md](../docs/backend-explained.md).
Там схема запроса, синтаксис Go, все маршруты и тела JSON, полный цикл работы,
хранение сессий/фото и разбор каждой строки семи файлов `cmd/server`.

## Запуск

Подготовьте отдельную БД и примените миграции 000001–000010 по порядку.
Уже применённые миграции повторно не запускать. Сервер сам миграции не применяет.

```sh
cd backend
export DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:15432/DB_NAME?sslmode=disable'
export BACKEND_ADDR='127.0.0.1:8080'
export UPLOAD_DIR='/absolute/path/outside/git/photos'
go run ./cmd/server
```

Адрес по умолчанию — `127.0.0.1:8080`, папка фото — `../data/uploads`
относительно рабочей папки. `.env` автоматически не загружается.
`GET /health` возвращает `{"status":"ok"}`; БД проверяется при запуске.

## Реализовано

- Регистрация teacher/student, вход, выход и изменение своего профиля.
- Сессии в памяти Go на 24 часа; Django использует HttpOnly cookie.
- Приглашения, ученики, группы, состав и архивация групп.
- Банк без выдачи ответов/решений.
- Варианты, позиции, баллы, порядок, публикация, копирование и архив.
- Назначения ученику/группе, сроки, статусы, лимиты попыток и история.
- Ответы с ревизиями, сдача, автоматическая/ручная проверка и публикация результата.
- Приватные JPEG/PNG до 8 МиБ, связанные с ответом через существующий answer_data.

Django подключён к входу, профилю, группам, банку, конструктору и попыткам. Запуск
совместной доски описан в [инструкции](../frontend/solve-board/README.md). Парсер и SVG → TikZ —
отдельное направление MVP; этот HTTP-сервер не означает готовность всего MVP.

## Проверено

- `gofmt`, `go test ./...`, `go vet ./...`, сборка сервера.
- 84 HTTP-запроса к настоящему серверу на временной PostgreSQL: полный цикл
  двух учеников, права, ревизии, фото и отдельные результаты.
- Временная схема удалена, серверы остановлены. Сценарии после выполнения удалены
  по решению владельца; исходные тесты БД и парсера сохранены.
- Браузерная проверка недоступна в текущем окружении.

Сервер рассчитан на локальный запуск. Публичное размещение, ограничение частоты
входа, постоянные сессии, восстановление пароля и уборка сиротских файлов
не реализованы. Подробности и точные границы — в полном объяснении.
