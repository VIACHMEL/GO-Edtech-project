# Go backend: запуск, API и объяснение реализации

Django-регистрация теперь подключена к этому API и выполняет автоматический вход.
Вымышленные данные страниц удалены, данные БД сохранены. Подробное объяснение
новой формы и обработчика: [frontend/INTERACTIONS.md](../frontend/INTERACTIONS.md).


Состояние: 22 ноября 2026. Документ описывает **исполняемый Go API**, а не обещание готовности всех страниц или всего MVP.
Новые обработчики используют существующие `db`, `teacherdata`, `worksheetdata`, `learningdata`.
Новых сторонних библиотек и миграций нет. Фото — локальные файлы, ссылки на них — в существующем `answer_data`.

## Как читать документ

1. Сначала прочитайте схему, словарь синтаксиса и пример полного цикла.
2. Затем откройте нужный файл в разделе «Построчный разбор»: у каждой физической строки есть номер, точный код и объяснение.
3. Перед таблицей каждого файла перечислены его функции и предметный смысл. Таблица объясняет синтаксис в этом контексте.
4. Старый SQL не переписан в HTTP: его правила описаны в существующих контрактах. Ссылки на них приведены ниже.

**Построчная часть полностью покрывает семь файлов `backend/cmd/server/*.go`, включая пустые строки.**
Далее отдельно объясняется граница с готовыми сервисами/БД и Django. Это не построчный учебник всего старого репозитория, парсеров и Django.

## Что готово и чего здесь нет

Готовы API регистрации, входа, профиля, приглашений, учеников/групп, банка, вариантов,
позиций, назначений, попыток, ответов, фотографий, ручной/автоматической проверки и публикации.
История — списки назначений и попыток; баллы и комментарии — в результатах ответов после публикации.

Django уже подключён к входу, профилю, группам и банку внутри конструктора. Новые операции
с вариантами/назначениями/проверкой/фото доступны через API; **страницы полного цикла ещё не подключены**.
Парсер Школково и SVG → TikZ не заменены этими обработчиками. Их завершение и качество
остаются отдельными обязательными задачами MVP. Это не утверждение о готовом публичном размещении.

## Схема запроса

```text
Браузер --cookie--> Django --Authorization: Bearer token--> HTTP Go
                                                      |
                         currentUser -> session map -> db.GetUser
                                                      |
                         готовый Service -> db -> PostgreSQL
                                                      |
                        DTO -> sendJSON -> Python -> HTML
```

`backend_client.py` — Python-клиент Go API, не пакет Go. SQL он не выполняет.
В Go `sendJSON` записывает JSON в HTTP-ответ; Python `json.load` читает этот ответ обратно в словарь/список.
Владение объектом проверяет Go/SQL, а не путь кабинета Django и не радиокнопка role.

## Словарь синтаксиса Go

| Запись | Что означает |
| --- | --- |
| `package main`, `func main()` | Исполняемый пакет и точка входа |
| `x := value` / `x = value` | Объявить переменную / изменить уже объявленную |
| `value, err := call()` | Получить два результата: значение и ошибку |
| `nil` | Отсутствие указателя/ошибки/map/slice; это не пустая строка |
| `*db.DB`, `*http.Request` | Тип указателя на объект |
| `&input` / `*hash` | Получить адрес переменной / прочитать значение по указателю |
| `type X struct { ... }` | Объединить именованные поля в один тип |
| `` `json:"email"` `` | Тег поля: имя при JSON-преобразовании |
| `[]T` / `[32]byte` | Срез переменной длины / массив ровно из 32 байт |
| `map[string]session` | Словарь со строковым ключом и значением session |
| `map[string]any` | Значения разных типов; например ID-число и имя-строка |
| `make([]T, 0, n)` | Пустой срез, заранее вместимость n; не n готовых элементов |
| `append(list, value)` | Вернуть срез с добавленным элементом, результат нужно сохранить |
| `for _, value := range list` | Перебор; индекс отбрасывается через `_` |
| `hash[:]` | Срез всех элементов массива hash |
| `if value, ok := ...; ok` | Объявить локальные значения перед проверкой условия |
| `entry.(string)` | Проверить/получить конкретный тип внутри any; форма с ok не паникует |
| `&&`, `||`, `!` | И, ИЛИ, НЕ; логика с коротким вычислением |
| `return`, `continue`, `break` | Выйти из функции / перейти к следующей итерации / выйти из цикла |
| `defer file.Close()` | Закрыть файл при выходе из функции, включая return |
| `func(w, r) { ... }` | Функция без имени; здесь замыкание берёт store и sessionStore из main |
| `errors.Is(err, kind)` | Определить вид ошибки, включая обёрнутые через `%w` |
| `http.ResponseWriter`, `*http.Request` | Куда записать ответ / откуда читать запрос |
| `r.PathValue("id")` | Текст переменной части маршрута `{id}` |
| `r.URL.Query().Get("limit")` | Текст параметра URL после `?`; отсутствующий даёт `""` |
| `strconv.ParseInt(s, 10, 64)` | Десятичная строка → int64; 64 бита, не 64 цифры |
| `strconv.Atoi(s)` | Десятичная строка → int |
| `strconv.FormatInt(id, 10)` | int64 → десятичная строка |

Время JSON — RFC3339, например `2026-12-01T18:00:00+03:00`; необязательный указатель
может быть `null`. Баллы — строки `"2.50"`, чтобы не терять точность PostgreSQL NUMERIC.
ID — JSON-числа; роль/ID исполнителя не берутся из тела запроса.

## Запуск

Нужны Go 1.26 и PostgreSQL с применёнными по порядку миграциями `000001`–`000009`.
Сервер **не применяет миграции автоматически**. К существующей БД нельзя повторно
применять уже исполненные миграции; подготовка базы выполняется отдельно.

```sh
cd backend
export DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:15432/DB_NAME?sslmode=disable'
export BACKEND_ADDR='127.0.0.1:8080'
export UPLOAD_DIR='/absolute/path/outside/git/photos'
go run ./cmd/server
```

`DATABASE_URL` обязателен. BACKEND_ADDR по умолчанию `127.0.0.1:8080`.
UPLOAD_DIR по умолчанию `../data/uploads` относительно рабочей папки процесса;
при запуске из backend это корневая `data/uploads`, исключённая из Git.
Лучше задавать абсолютный путь. Папки создаются с правами 0700, фото — 0600.
`.env` сам по себе не читается. В логах запуска указан адрес, но успешность
проверяется запросом `GET /health`. Health не проверяет БД заново.

Хеш для заранее созданного аккаунта можно получить без запуска БД:

```sh
read -rs -p 'Password: ' account_password
printf '%s' "$account_password" | go run ./cmd/server -hash-password
unset account_password
```

Пароль — 8–128 **байт**, а не символов. Формат хеша:
`pbkdf2-sha256$<16 байт соли в hex>$<32 байта ключа в hex>`.
Число итераций фиксировано 600000; при будущем изменении нужно сохранить
совместимость старых хешей. Один SHA256 для паролей не используется.

## Сессии и cookie

Сессии хранятся в map: токен → {userID, expires}. Токен — 32 случайных байта в hex.
Mutex защищает только короткие обращения к map; запросы к БД выполняются вне блокировки.
Неизвестный, просроченный токен или отключённый аккаунт дают 401.
Срок — 24 часа. Выход удаляет только текущую сессию. Перезапуск Go завершает все входы.
Несколько устройств могут иметь разные сессии одного аккаунта.

Браузер хранит токен в cookie `go_session`: HttpOnly, SameSite=Lax, Path=/,
max-age=86400. Django передаёт его Go через Authorization. Для HTTPS задать
`COOKIE_SECURE=true`; формы Django защищены CSRF. Go API для прямого клиента
не принимает эту cookie как авторизацию — ожидает Bearer-заголовок.
IP не используется для определения личности.

### Тела основных запросов

```json
{"title":"Работа 1","subject":"math","max_attempts":2}
```

Это CreateWorksheetRequest и UpdateWorksheetRequest: обновление передаёт все три поля.

```json
{"task_version_id":17,"position":1,"max_score":"2.50","settings":{}}
```

Это AddWorksheetItemRequest. Здесь **ID версии**, не ID задачи. Порядок начинается с 1.
Версии банка фиксируются при составлении, снимки условия/ответа — при публикации.

```json
{"worksheet_id":5,"student_id":12,"distribution":"a3d8dd61-46ba-45cf-910c-af8a0f006fef","due_at":null}
```

Для группы заменить student_id на group_id и использовать маршрут `/assignments/group`.
UUID distribution выбирает клиент для одной операции; при повторе посылает тот же.
Повтор с иными параметрами — 409. UUID можно получить стандартным генератором клиента;
сервер не создаёт его заново при каждом повторе, иначе идемпотентность исчезнет.

```json
{"text":"42","data":{},"expected_revision":0}
```

Это SaveAnswerRequest. Ответ содержит новую answer_revision; её использовать в следующем
сохранении. Запоздавшая версия — 409. Сервер не перезаписывает чужой новый ответ.
Data — полное дополнительное содержимое ответа; `photos` в нём — список локальных имён.
Если нужно сохранить фото при записи текста, передавать актуальный data из GET answers.
DELETE ответа очищает текст и data. Файлы при этом могут остаться на диске, но без
ссылки из answer_data не выдаются; автоматической уборки таких файлов в этом API нет.

## Пример последовательности клиента

1. POST register для teacher/student, затем POST login каждого пользователя.
2. Teacher создаёт группу и приглашения с expires_at; student принимает токен.
3. Teacher получает банк и current_version_id нужных заданий.
4. Создаёт вариант, добавляет позиции, при необходимости меняет порядок.
5. Публикует вариант и назначает ученику/группе, сохранив distribution для повторов.
6. Student читает назначения, вызывает start, получает attempt.id и GET answers.
7. Сохраняет ответы с последней ревизией; фото загружает с expected_revision.
8. Вызывает submit; после сдачи изменения запрещены. Опоздание фиксирует БД.
9. Teacher читает answers, проверяет позиции и вызывает publish результата.
10. Student читает answers снова: теперь result содержит баллы и комментарии.

До публикации результата у StudentAnswer нет result. Эталонные ответы и решения
не выдаются ученику ни в банке, ни в попытке. У преподавателя предварительные баллы
и live_state доступны в своём назначении; это не WebSocket/SSE, а обычный GET.

## Фотографии: что происходит на диске и в БД

POST получает сырое тело, не multipart. Максимум 8 МиБ, MIME определяется по байтам.
Принимаются JPEG/PNG; имя — случайные 32 байта в hex + jpg/png. Пользовательское
имя файла не участвует в пути. Проверка MIME не является полным декодированием изображения.
Путь: UPLOAD_DIR / attemptID / worksheetItemID / случайноеИмя.

Файл записывается до SaveAnswer, затем имя добавляется в answer_data.photos.
SaveAnswer атомарно проверяет draft, активное назначение, владельца и ревизию.
Если сдача произошла одновременно с загрузкой, запись БД отклоняется, новый файл
удаляется. Если процесс аварийно завершится между записью файла и БД, возможен
невидимый сиротский файл; он не выдаётся без ссылки в answer_data.
Фото не монтируются как публичная папка Django. GET заново проверяет участника
попытки, позицию, ссылку из data и формат имени; после этого отдаёт файл с nosniff.

## Проверки и ограничения

Проведено 84 настоящих HTTP-запроса к собранному серверу с временной PostgreSQL:
регистрация, неверный пароль, запрет admin, приглашения/отзыв/повтор, чужие объекты,
варианты/позиции/публикация, идемпотентная выдача группе, две отдельные работы учеников,
конфликт ревизий, фото и чужое скачивание, запрет правок после сдачи, ручная проверка,
скрытие результатов до публикации и лимит попыток. Временная схема удалена, серверы остановлены.
Go test/vet/build и проверки Django выполняются отдельно; результаты — в README/backlog.
Тестовые сценарии после проверки удаляются по указанию владельца.

Браузерная проверка недоступна в текущем окружении. API не подключает все страницы.
Это локальный сервер: автоматических миграций, восстановления пароля, ограничения
частоты входа, постоянных сессий, очистки сиротских файлов, фоновой конвертации и
настройки публичного размещения здесь нет. Сессии не разделяются между процессами.
Публичное размещение и дополнительные механизмы согласуются отдельно.

`Service` — уже существующая структура с Store *db.DB. NewService только сохраняет
указатель, не подключается к PostgreSQL. Методы преобразуют Request DTO в аргументы
БД, а модели БД — в Response DTO. Новых сервисных обёрток для этого API не создано.

**hashPassword** — Проверяет длину пароля в байтах, создаёт 16 случайных байт соли, вычисляет 32 байта PBKDF2-SHA256 за 600000 итераций. Возвращает текстовый формат алгоритм$соль$ключ. Исходный пароль не сохраняется.

**checkPassword** — Разбирает хеш на три части, проверяет алгоритм и длины. С той же солью пересчитывает ключ из введённого пароля. ConstantTimeCompare сравнивает байты без досрочного выхода на первом несовпадении.

**login** — Разбирает JSON email/password. Ищет учётные данные через GetUserByEmail, проверяет пароль, активность и роль. Для неизвестного email всё равно выполняет вычисление хеша. Создаёт случайный токен, очищает истёкшие сессии и сохраняет userID/срок под блокировкой. Возвращает только токен.

**currentUser** — Читает Bearer-токен, находит сессию под mutex и отклоняет истёкшую. Затем получает пользователя из БД. Если аккаунт исчез или отключён, отзывает эту сессию. Не доверяет userID из URL или JSON.

**logout** — Удаляет текущий токен из словаря под mutex. Повторный выход допустим. Cookie удаляется клиентом Django после успешного ответа; Go не управляет браузерной cookie напрямую.

**sendJSON** — Общий вывод ответа: Content-Type JSON, запрет HTTP-кэширования, статус и сериализация значения. Это наша функция, не команда Go и не отдельный сервис. Ошибка записи клиенту здесь пока не обрабатывается.

**sendError** — Распознаёт известные ошибки через errors.Is и переводит их в HTTP 400/401/404/409. Неизвестную ошибку пишет в серверный журнал и возвращает общее сообщение 503, без SQL в ответе.

**readJSON** — Читает одно JSON-значение размером до 2 МиБ в переданную структуру. Отклоняет неизвестные поля и второй JSON после первого. При ошибке сама отправляет 400 и возвращает false. Это небольшая общая функция, чтобы не копировать декодирование в каждый обработчик.
