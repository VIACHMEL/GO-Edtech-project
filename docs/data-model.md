# Модель данных: черновик

Это логическая модель; SQL-схема, типы ID и миграции ещё не утверждены.

| Сущность | Назначение |
| --- | --- |
| User | Пользователь и роль |
| TeacherStudent | Разрешённая связь преподавателя и ученика |
| Invitation | Ограниченное по сроку приглашение, статус использования |
| Group / Membership | Группа и участники |
| SourceTask | Источник + внешний ID; ключ защиты от дублей |
| TaskVersion | Неизменяемая версия условия, тем, номера, ответа и критериев |
| Asset | Исходное изображение или вложение, checksum и происхождение |
| Conversion | Исходник, версия модели/конвертера, TikZ, превью, статус проверки |
| Worksheet / WorksheetItem | Работа и конкретные версии задач, порядок и баллы |
| Assignment | Кому выдана работа, срок и правила выполнения |
| Attempt / Answer | Попытка ученика и ответы на задания |
| Attachment | Решение с привязкой к ответу и владельцу |
| Review | Предварительная/подтверждённая оценка, комментарий и проверяющий |

Групповое назначение создаёт персональные записи выполнения. Поведение при изменении состава группы после назначения нужно согласовать.

Для конвертации предлагаются состояния queued → processing → needs_review → approved/rejected, а технические сбои — failed с возможностью повтора. Успешная компиляция не означает математической корректности.

Для попытки предлагаются draft → submitted → reviewed. Повторная сдача и повторное открытие учителем должны иметь явные правила. Статусы и имена пока не являются контрактом API.
