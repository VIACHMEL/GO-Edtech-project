# Назначения, попытки и ответы: слой хранения Go

Модуль backend/internal/db использует users, teacher_students, groups, worksheet_items.
Новые миграции: 000007_worksheets, 000008_assignments_attempts и
000009_attempt_limits_and_lateness, после 000001–000006.
Они добавляют FK на существующих пользователей, версии задач и группы.
Это операции хранилища, не HTTP-контракт и не готовая система авторизации.
Идентификатор вызывающего пользователя всегда берётся из проверенного сервером сеанса.
Права повторно проверяются в Go-хранилище на каждом объекте.

## Назначения

`AssignWorksheet(ctx, teacher, worksheet, student, distributionUUID, dueAt)`
выдаёт опубликованный собственный вариант активному связанному ученику.
`AssignWorksheetToGroup(ctx, teacher, worksheet, group, distributionUUID, dueAt)`
атомарно создаёт персональные назначения активным связанным участникам собственной
активной группы. Пустая группа не выдаётся. Последующие изменения состава группы
не изменяют уже созданные назначения.
При выдаче max_attempts копируется из опубликованного варианта в каждое назначение.
Лимит задаётся преподавателем при создании варианта, изменяется только в черновике
и применяется отдельно к каждому ученику, в том числе при групповой выдаче.

distributionUUID создаёт вызывающий сервис один раз на операцию выдачи (UUID).
Повтор с тем же ключом и параметрами возвращает прежние записи; другой
получатель/вариант/преподаватель/срок с тем же ключом — ErrConflict.
Повтор групповой выдачи не добавляет новых участников в старую выдачу.
Для новой выдачи нужен новый UUID. Дата сравнивается с точностью PostgreSQL (микросекунды).
Если срок уже изменили через UpdateAssignmentDeadline, повтор первоначального
запроса с прежним сроком считается конфликтом; ключ выдачи не является журналом API-запросов.

Чтение:
- GetAssignment(ctx, actor, assignmentID);
- ListStudentAssignments(ctx, student, beforeID, limit);
- ListTeacherAssignments(ctx, teacher, beforeID, limit).

Списки: id DESC, beforeID=0 — начало, лимит по умолчанию 20, максимум 100.
Ученик видит только свои назначения, активный преподаватель — свои назначения
ученикам с действующей связью teacher_students.

SetAssignmentStatus(ctx, teacher, id, status) принимает active/closed/cancelled.
CloseAssignment — сокращение для closed.
UpdateAssignmentDeadline(ctx, teacher, id, dueAt) изменяет срок; nil убирает срок сдачи.
Закрытие/отмена блокируют редактирование и сдачу, но сохраняют историю и возможность
проверить ранее сданные ответы. Сам вариант при выдаче не копируется, поскольку
опубликованные позиции и их снимки неизменяемы через публичные методы.

## Попытки и сроки

- StartOrResumeAttempt(ctx, student, assignmentID) возвращает существующий draft
  либо создаёт следующую попытку в пределах max_attempts. После сдачи ученик может
  начать следующую попытку самостоятельно. Параллельные запросы возвращают один draft.
- SubmitAttempt(ctx, student, attemptID) атомарно сдаёт уже сохранённые ответы.
  Повтор не создаёт ещё одну сдачу и не меняет её время.
- ReopenAttempt(ctx, teacher, assignmentID) создаёт НОВЫЙ draft со следующим
  attempt_no в пределах того же лимита; обойти лимит этим методом нельзя.
  Прежние ответы и результаты сохраняются.
  Если draft уже открыт, возвращается он же. Новая попытка начинается с пустыми ответами.
- GetAttempt(ctx, actor, attemptID), ListAssignmentAttempts(ctx, actor, assignmentID)
  доступны только владельцу-ученику и преподавателю назначения.

Состояния: draft → submitted → reviewed. Преподаватель публикует результат
после проверки. Каждая созданная попытка расходует одно место в лимите;
возобновление draft и повтор сдачи не расходуют дополнительные места.
При исчерпании лимита новая попытка возвращает ErrAttemptLimit.
Проверка лимита и создание попытки выполняются под блокировкой назначения,
поэтому конкурентные запросы преподавателя и ученика не создают лишних попыток.

Истечение dueAt не блокирует начало, сохранение ответов и сдачу активного назначения.
При первой сдаче PostgreSQL фиксирует submitted_at и is_late: true, если этот момент
позже dueAt; при отсутствии срока — false. До сдачи is_late=false.
Повтор сдачи и последующее изменение срока не меняют зафиксированную отметку.
Для следующих попыток используется актуальный срок. Закрытие или отмена назначения
по-прежнему блокируют начало, изменение и первую сдачу.

Миграция 000009 задаёт старым вариантам/назначениям лимит 1 и сохраняет историю
всех прежних попыток, включая превышающие этот лимит. Для исторических сдач
is_late вычисляется по сохранённому submitted_at и текущему dueAt: прежняя история
изменений срока недоступна. Down удаляет новые поля; повторный up восстановит
значения по умолчанию, а не ранее настроенные лимиты. Сначала примените миграции,
затем обновлённый Go-код. CreateWorksheet/UpdateWorksheet требуют maxAttempts;
прежняя ошибка ErrRetakeRequired заменена на ErrAttemptLimit.

Отключённый аккаунт не имеет доступа. После отвязки преподаватель теряет доступ
к ответам бывшего ученика, а ученик сохраняет чтение своей истории; выполнять
старую работу до восстановления связи нельзя. Архивирование группы не отменяет
выданные персональные назначения.

## Ответы и ревизии

SaveAnswer(ctx, student, attemptID, AnswerInput) принимает WorksheetItemID,
Text, необязательный Data (JSON-объект), ExpectedRevision.
Лимиты: 10000 Unicode-символов текста и 1 MiB сериализованного Data.
Пока поддерживается один ответ на позицию: part_key = ''. Подзадачи будут
требовать отдельного согласования схемы проверки и суммирования баллов.

На старте для каждой позиции создаётся пустая строка ответа с ревизией 0.
SaveAnswer возвращает SavedAnswer с новым номером ревизии.
Устаревшая редакция — ErrRevisionConflict. Повтор непосредственно предыдущего
идентичного сохранения возвращает ту же ревизию. Пустое сохранение уже пустого
ответа с nil Data ничего не меняет.
ClearAnswer(ctx, student, attemptID, itemID, revision) очищает текст и Data
с теми же правилами ревизий. Изменение ответа сбрасывает прежнюю оценку и комментарий.

Позиция обязана принадлежать варианту данного назначения; это дополнительно
обеспечивают составные FK в PostgreSQL. Сохранение, сдача и проверка блокируют
назначение и попытку в одной транзакции, чтобы не потерять параллельные изменения.
Ручные изменения после сдачи заблокированы.

Data — непрозрачные структурированные данные, не загрузка файла. Загрузка/проверка
фотографий, хранилище files, доступ к вложениям и холст относятся к другим модулям.

## Проверка и публикация результата

При SubmitAttempt автоматически проверяются short_answer по точному сравнению
текста после удаления крайних пробелов. Приведение регистра, дробей, запятых и
составных ответов пока не согласовано и не выполняется.
Неверный краткий ответ получает 0, верный — max_score.
Пустое решение без Data получает 0. Развёрнутое непустое решение ждёт ручной оценки.

- AutoGradeAnswer(ctx, teacher, attemptID, itemID, revision) — предварительная
  проверка краткого ответа, включая draft; ручную оценку не перезаписывает.
- ReviewAnswer(ctx, teacher, attemptID, itemID, revision, score, comment) — оценка
  сданной работы, включая ручное переопределение краткого ответа.
  score — строка NUMERIC с максимум двумя знаками после точки, 0..max_score.
  Комментарий — до 5000 Unicode-символов.
- PublishAttemptResult(ctx, teacher, attemptID) — все позиции должны иметь
  актуальную оценку своей ревизии. После публикации попытка reviewed и оценки
  неизменяемы; повтор публикации ничего не меняет.

GetAttemptAnswers(ctx, student, attemptID) возвращает специальный StudentAnswer:
условие из опубликованного снимка, текст/Data ученика, ревизию и максимум баллов.
До публикации поля result нет вообще. После публикации result содержит
правильность, балл и комментарий. Эталонный ответ и решение не входят в эту модель.

GetTeacherLiveState(ctx, teacher, attemptID) возвращает сохранённые ответы,
ревизии, оценки и предварительный LiveState: -1 нет ответа, 0 неверно,
1 верно, nil ожидает ручной проверки. Для неоценённого краткого ответа
состояние вычисляется по снимку эталона; это не опубликованная оценка ученика.
SSE/WebSocket и обработчики HTTP здесь не реализованы.

## Ошибки

errors.Is: ErrNotFound (включая чужой объект/неактивный аккаунт), ErrValidation,
ErrConflict (ключ выдачи), ErrWorksheetLocked, ErrAttemptLocked,
ErrWorkClosed, ErrRevisionConflict, ErrAttemptLimit, ErrIncompleteGrading.
WorksheetItem сохраняет отдельную ErrWorksheetConflict для занятой позиции.

Для подключения к веб-приложению нужны серверные сеансы и HTTP-обработчики.
