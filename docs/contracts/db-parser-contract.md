# Контракт БД заданий ЕГЭ — для парсеров

Документ описывает, в каком виде парсер должен отдавать задания и что
происходит с ними на стороне базы. Читать целиком перед началом работы.

Версия: 1.0
Пакет в коде: `internal/db`
Точка входа: `store.AddTask(ctx, task)` / `store.AddTasks(ctx, tasks)`

## 1. Поля

### 1.1 Обязательные

Без них задание не будет сохранено (вернётся ошибка `ErrValidation`).

| Поле           | Тип    | Описание                                                                 |
|----------------|--------|--------------------------------------------------------------------------|
| `source_url`   | string | URL страницы, откуда взято задание. Полный, с протоколом.                |
| `source_site`  | string | Домен источника, например `site.ru`. Дублирует `source_url`, но нужен для группировки и статистики. |
| `subject`      | string | Код предмета.                                                            |
| `task_number`  | int    | Номер задания в экзамене (1..N).                                         |
| `content_text` | string | Текст задания. Без ведущих/хвостовых пробелов, без HTML-разметки.        |
| `answer`       | string | Правильный ответ.                                                        |

### 1.2 Сильно рекомендуемые


| Поле        | Тип    | Описание                                            |
|-------------|--------|-----------------------------------------------------|
| `year`      | int    | Год экзамена.                                       |
| `exam_type` | string | Тип экзамена.                                       |
| `task_type` | string | Тип ответа.                                         |
| `solution`  | string | Решение / объяснение, если есть на странице.        |

### 1.3 Опциональные — кладём в `metadata`

Свободное поле `metadata` — `map[string]any` (в БД `JSONB`).
Сюда кладите всё, что парсер достаёт, но что не вошло в фиксированные колонки.

Известные ключи (используйте именно эти имена, чтобы фильтры на фронте работали):

| Ключ            | Тип            | Описание                                  |
|-----------------|----------------|-------------------------------------------|
| `difficulty`    | string         | `"base"` / `"advanced"` / `"high"`, если указана. |
| `topics`        | []string       | Темы/подтемы.                            |
| `options`       | []string       | Варианты ответа для заданий с выбором.   |
| `images`        | []string       | URL картинок.                            |
| `formula`       | string         | LaTeX или исходная разметка формул.      |
| `variant_number`| int            | Номер варианта, если задание из варианта. |


### 1.4 Что парсер НЕ должен передавать

Эти поля заполняются на стороне БД. Если парсер их пришлёт — они будут проигнорированы (или перезаписаны).

- `id`
- `content_hash` — считается автоматически.
- `created_at`, `updated_at` — ставит база.
- Любые внутренние id (`subject_id`, `task_type_id`, `exam_type_id`) — маппинг
  делается на стороне БД по кодам из §3.

## 2. Справочники кодов

Используйте **только** эти значения. Если нужного нет — согласуйте добавление,
не придумывайте своё.

### 2.1 `subject`

| Код          | Предмет            |
|--------------|--------------------|
| `math`       | Математика (профиль) |
| `math_base`  | Математика (база)  |
| `russian`    | Русский язык       |
| `physics`    | Физика             |
| `chemistry`  | Химия              |
| `biology`    | Биология           |
| `history`    | История            |
| `social`     | Обществознание     |
| `informatics`| Информатика        |
| `geography`  | География          |
| `foreign`    | Иностранный язык   |
| `literature` | Литература         |

### 2.2 `exam_type`

| Код   | Тип  |
|-------|------|
| `ege` | ЕГЭ  |
| `oge` | ОГЭ  |

### 2.3 `task_type`

| Код            | Что значит                              |
|----------------|------------------------------------------|
| `short_answer` | Краткий ответ (число, слово, строка).    |

| `choice`       | Выбор одного или нескольких вариантов.   |

## 3. Правила для пустых значений

| Тип | Значение |
| :--- | :--- |
| Строки (`SourceURL`, `ContentText`, `Solution`) | `""` (пустая строка) |
| Ответ (`Answer`) | `""` (пустая строка) |
| Числа (`Year`, `TaskNumber`) | `0` |
| Списки в `Metadata` (`topics`, `images`) | Не добавлять ключ в мапу (не передавать `nil` или `[]string{}`) |
| Все текстовые поля (перед отправкой) | `strings.TrimSpace()` |

---

## 4. Что считается дублем

Задание считается уже существующим, если совпадает пара
**(`source_url`, `content_hash`)**.

- `content_hash` вычисляется автоматически из нормализованного
  `subject` + `task_number` + `content_text`. Парсеру это делать не нужно.
- Если то же задание встретилось повторно — запись **обновляется**
  (`answer`, `solution`, `metadata`, `updated_at`). `id` и `created_at`
  сохраняются.
- Если `source_url` совпадает, а текст отличается — это **два разных задания**
  (например, страница-вариант с разными заданиями под одним URL — так делать
  не надо, но если так вышло, база не сломается).

## 5. Пример структуры

### 1.1 Общий вид структуры

Структура имеет следующий вид (для наглядности показано какие из полей заполняются парсером)

```go
type Task struct {
	// ЗАПОЛНЯЕТ ПАРСЕР

	// Обязательные
	SourceURL   string 
	SourceSite  string 
	Subject     string 
	TaskNumber  int    
	ContentText string 
	Answer      string 

	// Рекомендуемые
	Year        int    
	ExamType    string 
	TaskType    string 
	Solution    string 
	
	// Опциональное
	Metadata    map[string]any 

	// ЗАПОЛНЯЕТ БАЗА
	
	ID          int64     
	ContentHash string    
	CreatedAt   time.Time 
	UpdatedAt   time.Time 
}
```

Отправление задания в базу данных выполняется следующей функцией: store.AddTask(ctx, task).

### 1.2 Пример заполнения и отправки

```go
task := &db.Task{
    SourceURL:   "https://site.ru/ege/2024/task-5",
    SourceSite:  "site.ru",
    Subject:     "math",
    ExamType:    "ege",
    Year:        2024,
    TaskNumber:  5,
    TaskType:    "short_answer",
    ContentText: "Найдите значение выражения ...",
    Answer:      "42",
    Solution:    "По формуле ...",
    Metadata: map[string]any{
        "difficulty": "base",
        "topics":     []string{"алгебра", "уравнения"},
        "images":     []string{"https://site.ru/img/1.png"},
    },
}

id, err := store.AddTask(ctx, task)
