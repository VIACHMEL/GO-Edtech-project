# Контракт данных пользователей и групп для Go API — версия 0.2

Обновлено 18 ноября 2026 года. Документ описывает внутреннее взаимодействие пакета БД и слоя подготовки данных. **Это не описание уже работающих HTTP-маршрутов.**

## 1. Разделение ответственности

- `internal/db/teacher_views.go` — существующие SQL-запросы: действующие связи преподавателя с учениками, группы и их участники, включая архивные группы.
- `internal/db/teacher_overview.go` — проверка поддерживаемых фильтров и роли преподавателя, поиск и подсчёт данных в методах `ListTeacherStudentsPage` и `ListTeacherGroupsPage`. Пока поиск выполняется на Go после SQL-запроса с JOIN, без постраничной выдачи. Для небольшого MVP это допустимо, но при росте данных потребуется фильтрация в SQL.
- `internal/teacherdata/service.go` — вызов методов БД и преобразование результатов в структуры JSON. Здесь нет SQL, проверки роли, предметной фильтрации или самостоятельного подсчёта.
- `internal/teacherdata/dto.go` — структуры с JSON-тегами, определяющие внешний формат ответа.
- HTTP-обработчики, авторизация и сессии реализуются отдельно. ID преподавателя должен поступать из подтверждённой сессии.

## 2. Статусы пользователей и фильтр «Активные»

В текущей PostgreSQL существуют три разных статуса:

| Поле | Возможные значения | Смысл |
| --- | --- | --- |
| `users.status` | `active`, `disabled` | Состояние учётной записи |
| `teacher_students.status` | `active`, `removed` | Состояние учебной связи с преподавателем |
| `groups.status` | `active`, `archived` | Состояние учебной группы |

**Статуса «ученик на паузе» в БД нет.** Список преподавателя содержит только активные учётные записи учеников с действующей связью с ним.

Параметр `status` поддерживает пустое значение, `all` и `active`. Эти варианты **на данный момент равнозначны** и сохранены для совместимости с существующим интерфейсом. Неизвестное значение вызывает `db.ErrValidation`.

В ответе `total` — число всех доступных учеников **до применения поиска**. `active_count` совпадает с `total` по определению и временно оставлен ради совместимости с Django. Это **не самостоятельный показатель учебной активности**. Он может быть удалён после согласованного обновления frontend.

**Нельзя** показывать прекращённые связи (`teacher_students.status='removed'`) бывшему преподавателю только ради реализации вкладки «Все»: это изменит модель доступа. В будущем статус приостановки занятий следует определить отдельно, включая правила доступа к работам и группам.

## 3. Отображаемое имя и поле инициалов

`users.name` — произвольное **отображаемое имя**. Это не гарантированная комбинация «фамилия + имя + отчество». Деление по пробелам ошибочно для составных фамилий, многословных имён, других языков и пользователей с одним именем.

Ради совместимости поле JSON `initials` сохранено, но теперь означает **одну первую букву отображаемого имени**, приведённую к верхнему регистру. Пробелы по краям удаляются; пустое имя даёт пустую строку. Это символ аватара, **а не настоящие инициалы**.

Примеры:

| Отображаемое имя | `initials` |
| --- | --- |
| `Иван Петров` | `И` |
| `Мария де ла Крус` | `М` |
| `van der Waals` | `V` |
| `Émile Zola` | `É` |

Имена не разбираются на части и не записываются в журналы из слоя DTO. В перспективе предпочтительнее использовать стандартный аватар или согласовать отдельные необязательные поля имени. Автоматически восстанавливать фамилию по `users.name` нельзя.

## 4. Предлагаемые HTTP-маршруты

Эти маршруты **пока должны быть подключены разработчиком сервера**, а не считаются существующими:

| HTTP-маршрут | Метод Go | Доступ и результат |
| --- | --- | --- |
| `GET /api/v1/me` | `teacherdata.GetProfile(ctx, userID)` | Пользователь из подтверждённой сессии; профиль без пароля |
| `GET /api/v1/teacher/students?q=&status=all` | `GetTeacherStudents(ctx, teacherID, q, status)` | Активный преподаватель; его действующие связи с учениками и активные группы |
| `GET /api/v1/teacher/groups?q=&status=all` | `GetTeacherGroups(ctx, teacherID, q, status)` | Активный преподаватель; фильтры групп `all`, `active`, `archived` |

Все идентификаторы — `int64`, в JSON передаются как числа. Поля `grade` и `subject` могут быть `null`. Пустые списки возвращаются как `[]`, а не `null`.

Для учеников поиск выполняется по отображаемому имени, email и названиям активных групп. Для групп — по названию и предмету. Счётчики `total`, `active_count`, `archived_count` рассчитываются **до поиска и фильтрации**.

Архивные группы видны в списке групп, но не входят в список действующих групп ученика. Состав архивной группы отражает действующие связи с преподавателем **на текущий момент**, а не исторический состав при архивировании.

## 5. Совместимость с frontend

Названия JSON-полей не изменены относительно версии 0.1. **Изменилось только значение поля `initials`**: вместо предполагаемого сокращения нескольких слов теперь возвращается одна буква для аватара. Разработчика frontend нужно предупредить об этом изменении.

Показатели `attention`, прогресс, расписание, заметки, оценки и учебная статистика в этом модуле не предоставляются. Подменять отсутствующие данные выдуманными значениями нельзя.

## 6. Обработка ошибок

- Неизвестный `status`: `errors.Is(err, db.ErrValidation)`.
- Не найден пользователь-преподаватель: `errors.Is(err, db.ErrNotFound)`.
- Пользователь отключён или не имеет роль `teacher`: `errors.Is(err, db.ErrValidation)`.
- Сбои БД передаются в обёрнутой ошибке; сырой SQL и строку подключения (DSN) нельзя возвращать клиенту.

HTTP-обработчик обязан брать ID пользователя из подтверждённого контекста, а не доверять произвольному ID из URL или тела запроса.

## 7. Проверка и интеграция

Запуск из директории `backend/` после применения миграций 000001–000009 в **отдельной тестовой PostgreSQL**:

```sh
export EDTECH_TEST_DSN='postgres://YOUR_USER:YOUR_PASS@127.0.0.1:15432/edtech_test_db?sslmode=disable'
go test ./internal/db ./internal/teacherdata -v -count=1
go vet ./internal/db ./internal/teacherdata
gofmt -l internal/db/teacher_overview.go internal/db/teacher_overview_test.go internal/teacherdata/*.go
```

Интеграционный тест `TestTeacherDataIntegration` должен закончиться **PASS**, а не **SKIP**. Переменная `EDTECH_TEST_DSN` обязательна для теста с PostgreSQL.

Ранее `.gitignore` содержал правило `*test.go`, из-за которого новые Go-тесты не попадали в коммиты. Нужно удалить это правило и явно добавить тестовые файлы в Git, проверив `git diff --cached --stat`.

**Новые миграции для этой переработки не требуются.** Сигнатуры существующих `ListTeacherStudentViews` и `ListTeacherGroupViews` не изменяются. Новые методы чтения добавляются к пакету БД.
