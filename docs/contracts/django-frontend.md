# Заготовка Django: маршруты и граница Go

Статус: реализованы маршруты интерфейса; бизнес-операции Go и вход ещё не согласованы. Предметные данные и схема БД не меняются.

| Метод и путь | Поведение |
| --- | --- |
| GET / | 302 → /welcome/ |
| GET /welcome/ | Общая стартовая страница |
| GET /preview/ | 302 → /preview/teacher/ |
| GET /preview/teacher/ | Публичный макет кабинета преподавателя |
| GET /preview/teacher/tasks/, works/, students/ | Разделы макета без личных данных |
| GET /preview/student/ | Публичный макет кабинета ученика |
| GET /preview/student/works/, results/ | Разделы макета без личных данных |
| GET /dashboard/, /teacher/, /student/ | 302 → /login/?next=… |
| GET /teacher/tasks/, works/, students/; /student/works/, results/ | Переадресация на вход, без выдачи данных |
| GET /login/ | Страница недоступного пока входа; пароли не собираются |
| POST /login/ | 503, без входа и cookie; без CSRF-подтверждения — 403 |
| GET /health/ | 200: `{"status":"ok","service":"frontend"}`; без обращения к Go |
| GET /ready/ | 200: `{"status":"ready"}` только после успешной проверки Go |

Неподдерживаемый метод — 405. GET адресов без завершающего слеша — 301 на канонический адрес, если маршрут существует. Неизвестный адрес/раздел макета — 404. Есть страницы 400/403/404/500; при DEBUG=true Django может показывать диагностические страницы.

`next` сохраняется для будущего входа: только локальный абсолютный путь без хоста; внешние/некорректные адреса и возврат на /login/ заменяются на /dashboard/. Сейчас перехода после успешного входа нет, потому что входа нет. Роли из URL/cookie не используются для доступа.

## Проверка Go

`GO_API_BASE_URL` — серверный адрес Go (HTTP/HTTPS, без учётных данных, query и fragment). `GO_API_HEALTH_PATH` — относительный к base URL путь с одним начальным `/`, без query/fragment. Например, base `http://127.0.0.1:8080/api` и path `/health-check` дают `/api/health-check`. Это пример настройки, не утверждённый маршрут Go.

Пустой/некорректный адрес проверки: /ready/ отвечает 503 с `reason=go_not_configured`. Ошибка сети, тайм-аут, перенаправление или ответ вне 2xx: 503 с `reason=go_unavailable`. Тело ответа и внутренние адреса Go наружу не передаются. Проверка принимает любой 2xx без требований к телу, пока отдельный формат не согласован. Ответы проверок не кэшируются.

Клиент обращается напрямую к настроенному Go, не использует HTTP_PROXY/HTTPS_PROXY и не следует перенаправлениям; тайм-аут по умолчанию 2 секунды, допустимо более 0 и не более 30 секунд. URL не берётся из браузерного запроса. Health не доказывает готовность предметных функций.

## Следующий контракт

Согласовать вход, выход, подтверждение личности, срок действия и хранение сеанса, затем API каталога и работ. Go проверяет пользователя и права на каждый объект. Django не получает права изменять предметную БД. Эти контракты не подменяются фиктивными пользователями или выдуманными endpoints.
