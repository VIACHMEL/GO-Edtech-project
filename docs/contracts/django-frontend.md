# Django → Go: вход, пользователи и группы

Go управляет паролями, сессиями, правами и PostgreSQL. Django передаёт HTTP JSON
и отображает существующие страницы. Доступные маршруты:

| Метод и путь Go | Вход → ответ |
| --- | --- |
| GET /health | `{status:"ok"}`, без проверки БД при запросе |
| POST /api/v1/login | `{email,password}` → `{token}` |
| POST /api/v1/logout | удалить текущую сессию → `{ok:true}` |
| GET /api/v1/me | свой ProfileDTO |
| GET /api/v1/teacher/students | StudentListResponse |
| GET /api/v1/teacher/groups | GroupListResponse |
| GET /api/v1/teacher/tasks | список публичных полей заданий |
| POST /api/v1/teacher/groups | `{name,subject?}` → `{id,name,subject}`, 201 |
| PUT /api/v1/teacher/groups/{id} | `{name,subject?}` → `{id,name,subject}` |
| POST /api/v1/teacher/groups/{id}/members | `{student_id}` → `{ok:true}` |
| DELETE /api/v1/teacher/groups/{id}/members/{student_id} | `{ok:true}` |

Формат списков и фильтры: [frontend-users-api.md](frontend-users-api.md).
Списки доступны только активному преподавателю; ID определяется по сессии.
Пароль и его хеш не входят в публичные ответы. Ответы API не кэшируются.
Ошибки `{error:"…"}`: 400 ввод, 401 вход, 403 роль, 404 объект, 409 конфликт, 503 внутренняя ошибка/БД.

Токен — 32 случайных байта в hex. Сессия хранит userID и срок в памяти Go;
действует 24 часа. При выходе удаляется; после перезапуска требуется новый вход.
Перед каждым закрытым запросом проверяется активность аккаунта в БД.

Django: GET/POST `/login/`, POST `/logout/`, профиль `/teacher/` и `/student/`,
списки `/teacher/students/` и `/teacher/groups/`. Браузер сохраняет cookie
`go_session` с HttpOnly, SameSite=Lax, Path=/ и max-age=86400. Django извлекает
токен и передаёт Go через `Authorization: Bearer …`. При выходе cookie удаляется.
`COOKIE_SECURE=true` включает Secure для HTTPS. POST-формы защищены CSRF.

`GO_API_BASE_URL` по умолчанию `http://127.0.0.1:8080`, тайм-аут 3 секунды.
Клиент не использует прокси окружения и не следует перенаправлениям.
401 направляет на вход; остальные ошибки отображаются без подстановки примеров.
Календарь, выполнение и проверка пока остаются демонстрационными.
Конструктор читает банк Go, но сохраняет вариант пока только в браузере.
Запись доступна только в свои активные группы; чужие и архивные возвращают 404.
Связь с учеником при добавлении проверяет существующий SQL-метод. Формы создания,
изменения и состава защищены CSRF; после успешной записи — перенаправление к группе.
Схема БД, DTO списков и прежние GET-маршруты не изменились. Старое описание preview/ready не
соответствовало фактическим маршрутам и заменено этим контрактом.


Банк принимает `subject`, `year`, `task_number`, `task_type`, `limit` (1–100,
по умолчанию 20). Некорректный числовой фильтр — 400. Пустая выдача — `[]`.
Элемент: `id,current_version_id,subject,task_number,year,task_type,content_text,
source_site,source_url`. Ответов, решений, метаданных и max_score нет; баллы
назначаются позиции варианта. Обработчик использует существующий `db.ListTasks`.
Строки условий экранируются; произвольный HTML не исполняется.

## Расширение Go API: полный цикл работ

Добавлены регистрация/профиль, приглашения, варианты/позиции, назначения,
попытки/ответы, проверка/публикация и приватные фотографии. Полный актуальный
список методов, входных/выходных DTO, ошибок и прав приведён в
[backend-explained.md](../backend-explained.md#полный-список-маршрутов).
Существующие маршруты чтения и групп сохранены, схема БД не менялась.
Конфликты состояния, ревизии, лимита попыток и неполной проверки возвращают 409;
для фото также возможны 413 (размер) и 415 (тип).
Это расширение API не подключает автоматически соответствующие страницы Django.
