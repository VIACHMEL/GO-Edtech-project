# Черновой API авторизации и профилей

Сейчас это учебный каркас без настоящей регистрации, авторизации или БД. Он не является согласованным production API.

GET /health и GET /api/v1/demo/students работают без входа и возвращают фиктивные данные. Последний адрес не должен использоваться для реальных профилей.

Следующие маршруты отвечают 501 с кодом not_implemented: POST /api/v1/auth/register-tutor, /api/v1/auth/login, /api/v1/auth/logout; GET /api/v1/me; GET и POST /api/v1/students; POST /api/v1/students/{id}/credentials, /api/v1/students/{id}/invitations, /api/v1/invitations/preview, /api/v1/invitations/accept. Пароли и персональные данные не отправлять.

Предлагаемый поток: преподаватель создаёт профиль, выдаёт временные данные входа или одноразовое приглашение, ученик активирует доступ и устанавливает свой пароль. Необходимо согласовать существующие аккаунты учеников, владение профилями разных преподавателей, отзыв доступа и восстановление пароля.

До реализации: согласовать контракт, устойчивое хранилище и миграции, хеширование паролей, сессии, защиту приглашений, проверку владения объектами и сценарии ошибок; добавить проверки отрицательных случаев.
