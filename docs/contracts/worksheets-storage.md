# Хранение вариантов

Реализованы таблицы worksheets и worksheet_items и методы Go в backend/internal/db.
HTTP-маршруты и интерфейс конструктора подключены; черновики сохраняются в PostgreSQL.
Назначения, попытки и ответы описаны в [learning-storage.md](learning-storage.md).

## Схема

Миграция 000007_worksheets применяется после миграций 000001–000006.
Миграция 000009_attempt_limits_and_lateness добавляет max_attempts — количество
попыток, заданное преподавателем при создании варианта. Допустимо целое число
от 1 до 2147483647; 0 не означает неограниченное число попыток.
Для старых вариантов значение по умолчанию — 1. Сначала примените все миграции
000001–000009, затем запускайте обновлённый Go-код.
Вариант содержит teacher_id, title, subject, max_attempts, status, даты создания/изменения/публикации.
Позиция варианта ссылается на task_versions.id, а не tasks.current_version_id.
Удалить используемую версию нельзя: FK использует ON DELETE RESTRICT.
При удалении самого варианта его позиции удаляются каскадно; публичного метода
удаления варианта нет — для сохранения истории используется архив.

teacher_id ссылается на существующую users.id через FK ON DELETE RESTRICT.
Создание и все изменения разрешены только активному пользователю роли teacher.
Выбранные версии задач должны относиться к предмету варианта.

## Операции

- CreateWorksheet(ctx, teacherID, title, subject, maxAttempts) — новый draft.
- GetWorksheet(ctx, teacherID, id) — свой вариант.
- ListWorksheets(ctx, teacherID, beforeID, limit) — свои варианты, id DESC,
  beforeID=0 для первой страницы; лимит по умолчанию 20, максимум 100.
- UpdateWorksheet(ctx, teacherID, id, title, subject, maxAttempts) — изменение черновика.
- PublishWorksheet(ctx, teacherID, id) — публикация непустого черновика;
  повторная публикация не меняет время.
- ArchiveWorksheet(ctx, teacherID, id) — архивирование с сохранением истории.
- CloneWorksheet(ctx, teacherID, id, title) — атомарная копия в новый черновик
  с новыми ID позиций, прежними ссылками на версии и тем же лимитом попыток.
- AddWorksheetItem(ctx, teacherID, id, item) — добавить позицию.
- RemoveWorksheetItem(ctx, teacherID, id, itemID) — удалить позицию черновика.
- UpdateWorksheetItem(ctx, teacherID, id, itemID, maxScore, settings) — баллы и настройки черновой позиции.
- ReorderWorksheetItems(ctx, teacherID, id, itemIDs) — полный список ID
  позиций ровно по одному; атомарно присваивает порядок 1..N.
- ListWorksheetItems(ctx, teacherID, id) — позиции своего варианта по порядку.

AddWorksheetItem принимает TaskVersionID, Position (>0), MaxScore и Settings.
MaxScore — десятичная строка от "0" до "9999.99", не более двух знаков после точки.
Это сохраняет точность NUMERIC(6,2) без float64. При чтении возвращается, например,
"2.50". Settings — JSON-объект; nil превращается в пустой объект.
Удаление позиции оставляет промежутки; для уплотнения используется перестановка.
Одну версию задачи можно добавить несколько раз на разные позиции.

## Доступ, состояния и ошибки

teacherID должен поступать из доверенного серверного контекста авторизации,
а не из параметра клиента. Хранилище также проверяет активность и роль преподавателя.
Каждая операция хранения ограничена владельцем. Чужой ID возвращает тот же
ErrNotFound, что и несуществующий вариант, включая чтение списка его позиций.
Методы предназначены для преподавателя; их нельзя использовать как ученический
API, поскольку доступ к эталонным ответам требует отдельного контракта.

Опубликованный/архивный вариант нельзя изменять через методы редактирования
и работы с позициями. Изменение — через копирование в черновик.
Это относится и к max_attempts. При назначении ученику лимит копируется в
assignments.max_attempts; у каждого ученика собственный счётчик попыток.
Сигнатуры CreateWorksheet и UpdateWorksheet изменены: вызывающему коду нужно
явно передавать maxAttempts. HTTP-контракт пока не добавлен.
Публикация, редактирование и копирование блокируют строку варианта в транзакции:
одновременная публикация и изменение состава сериализуются.
Перестановка использует отложенное уникальное ограничение позиций.

Ошибки проверяются через errors.Is:
ErrValidation, ErrNotFound, ErrWorksheetLocked, ErrWorksheetConflict.
Нарушение позиции не публикует частичные изменения.
Создание, добавление позиции и копирование не имеют ключа идемпотентности:
автоматические повторы этих операций требуют будущего контракта API.

При публикации каждая позиция получает снимок условия, ответа, решения и типа
задания. Назначенные работы читают условие и проверяют ответ по этому снимку,
даже если банк затем изменит ту же task_versions. Поведение AddTask не меняется.
Прямой SQL-доступ администраторов не ограничивается проверками Go.

## Атомарный черновик конструктора

Миграция `000011_worksheet_revision` добавляет `worksheets.revision BIGINT NOT NULL
DEFAULT 0 CHECK (revision >= 0)` и BEFORE UPDATE триггер. Любой прежний метод,
изменяющий вариант или его позиции, обновляет строку варианта и тем самым ревизию.
Чтение и копирование не меняют ревизию исходного варианта.

Новые Go API (только активный владелец-преподаватель):

- `POST /api/v1/teacher/worksheets/draft` — создать непустой черновик, 201.
- `GET /api/v1/teacher/worksheets/{id}/draft` — метаданные с `revision` и `tasks`
  по порядку. Задача содержит `id`, `task_version_id`, `subject`, `task_number`,
  `task_type`, `content_text`, `max_score`, `settings`; ответы и решения не передаются.
- `PUT /api/v1/teacher/worksheets/{id}/draft` — заменить полный черновик, 200.

Тело сохранения: `title`, `subject`, `max_attempts`, обязательный `expected_revision`,
`items: [{task_version_id, max_score, settings}]` (1–100 позиций), `publish` (по
умолчанию false). Для создания ревизия 0, для обновления — полученная при чтении.
Ответ — WorksheetDTO с `id`, `revision` и остальными метаданными. Поле `revision`
также добавлено к прежним WorksheetDTO; прежние API сохраняют форму запросов.

Владение и состояние проверяются под блокировкой строки. Чужой ID — 404,
неверные данные — 400, устаревшая ревизия или недоступное для редактирования
состояние — 409. Ошибка откатывает и метаданные, и позиции. `publish: true`
сохраняет состав и замораживает снимки в той же транзакции. ID варианта сохраняется.
Старые методы публикации остаются идемпотентными. Повтор PUT со старой ревизией
возвращает 409; после ответа сохранения клиент использует новую ревизию.
