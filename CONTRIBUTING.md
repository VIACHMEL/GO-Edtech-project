# Как работать над проектом

Сейчас настройкой занимается владелец; участники пока не приглашаются.

## Цикл работы

1. Выбрать задачу с критериями готовности и зависимостями.
2. Обновить main при чистом рабочем дереве: git switch main, затем git pull --ff-only.
3. Создать ветку: git switch -c feature/12-task-bank.
4. Сделать небольшое законченное изменение, проверить поведение.
5. Просмотреть git diff, добавить нужные файлы, создать commit и отправить ветку.
6. Открыть PR с результатом и проверками. После обсуждения объединить с main.

Префиксы веток: feature/, fix/, docs/, chore/. Не использовать общую постоянную ветку на человека. Не переписывать чужую историю.

Один ответственный за задачу; второй участник проверяет её после подключения команды. Пока владелец один, проверяет собственные изменения по чек-листу PR. Обязательное чужое одобрение пока не настраивается.

## Готовность

- Выполнены критерии задачи и проверки затронутых модулей.
- Изменения API и данных описаны, при необходимости есть миграция.
- Ошибки и права доступа проверены.
- Нет секретов, датасетов и случайных файлов.
- Известные ограничения перечислены в PR.

Защита main, требуемые проверки и CODEOWNERS настраиваются отдельно после появления CI и команды, с учётом доступности настроек тарифа. Наличие этих документов само по себе не включает защиту GitHub.
