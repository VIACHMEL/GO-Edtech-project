# Школково: браузерный сбор заданий и импорт в PostgreSQL

Скрипты открывают обычный Edge или Chrome, раскрывают «Ответ и решение»,
подгружают карточки и сохраняют отрисованный HTML вместе с JSON. Парсер
извлекает условие, краткий ответ, решение и ссылки на изображения.
Скрипты не обходят авторизацию, CAPTCHA или ограничения доступа.

## Установка

Нужны Python 3.10+, установленный Microsoft Edge и Go для импортёра:

```powershell
python -m pip install -r pipelines/shkolkovo/requirements.txt
```

Все команды Python ниже выполняются из корня репозитория. Для Chrome добавьте
`--browser chrome`. Дополнительная установка браузера Playwright не требуется:
используется уже установленный Edge/Chrome.

## Один раздел

```powershell
python pipelines/shkolkovo/capture_and_parse.py 'https://3.shkolkovo.online/catalog/7772' --output-dir capture/ege-1 --number 1 --exam ege
```

Откроется видимое окно браузера. Скрипт ждёт загрузки страницы, нажимает
«Загрузить ещё» и раскрывает ответы с паузой не менее секунды.
Результат: `page-001.html`, `page-001.json` и отчёт в терминале.
Существующие файлы не перезаписываются.

- `--limit 3` — раскрыть только три карточки для пробы.
- `--max-loads 5` — предел нажатий «Загрузить ещё».
- `--manual` — дождаться Enter в терминале после открытия страницы.
  Если сайт просит проверку, пользователь выполняет её самостоятельно.
- Можно передать несколько URL одного номера и экзамена.

После ручного выбора подтемы проверьте соответствие `--number` и `--exam`.
Номер должен относиться к заданию экзамена, а не порядку карточки на странице.

## Следующие разделы и продолжение после остановки

```powershell
python pipelines/shkolkovo/batch.py 'https://3.shkolkovo.online/catalog/7772' --output-dir capture/batch --target 1000
```

Обработчик идёт по ссылкам «Следующий раздел» в одном сеансе браузера.
Номер определяется по заголовку страницы; этот режим предназначен только
для кратких ответов профильной математики ЕГЭ, номеров 1–12.
Каждый номер может включать несколько разделов.

После раздела сохраняются HTML, JSON, `progress.json` и общий `tasks.json`.
Повтор той же команды с той же папкой продолжает выгрузку.
`--attempts 2` задаёт число попыток открытия (максимум 3), между повторами
есть пауза. При сохраняющейся ошибке или проверке, требующей человека,
программа завершается; подтверждённые результаты остаются на диске.
`--max-sections 50` ограничивает число разделов, `--delay 1` — паузу.
Изменять в процессе захвата открытую страницу не следует.

Это ограниченный обход соседних разделов, а не гарантия полного каталога.
Если подгрузка не удалась, уже доступные карточки сохраняются, а в отчёте
остаются `load_error` и/или `more_available`. Такой раздел требует
отдельного продолжения. Переходы между страницами иногда заменяют карточки;
полнота большой выгрузки должна проверяться по отчётам и источнику.

## Формат и изображения

Карточки без URL, условия или краткого ответа пропускаются с отчётом.
JSON соответствует адаптеру `backend/cmd/import-shkolkovo`:

- `content_text`, `answer`, `solution` — извлечённый текст;
- `metadata.images` — адреса изображений условия;
- `metadata.solution_images` — адреса изображений решения;
- `metadata.section_url`, `metadata.section_title` — происхождение раздела
  при браузерном захвате.

Формулы могут быть SVG: alt включается в текст, исходные URL сохраняются.
Текст по alt не заменяет исходную разметку и может терять математическое
форматирование. Для точного просмотра сохраняется HTML. Файлы изображений
не скачиваются; постоянство ссылок не гарантируется.

При разборе HTML, сохранённого браузером с папкой ресурсов, локальные ссылки
сохраняются в `local_images` / `solution_local_images`. Импортёр блокирует
их запись в БД до переноса файлов в доступное хранилище.

Самостоятельный разбор готового HTML:

```powershell
python pipelines/shkolkovo/parse.py --html page.html --url 'https://3.shkolkovo.online/catalog/7772' --number 1 --exam ege --output tasks.json
```

`capture_page.py` сохраняет одну страницу после ручного раскрытия ответов.
Код `math` для ОГЭ ещё нужно согласовать: в контракте он обозначает профильную
математику. Развёрнутые ответы отдельно не поддерживаются.

## Импорт

Из папки backend:

```powershell
go run ./cmd/import-shkolkovo --file ../capture/batch/tasks.json
```

По умолчанию выполняется только проверка. Для записи задайте `DATABASE_URL`,
примените миграцию `pkg/db/migrations/000001_init_tasks.up.sql` к тестовой БД
и добавьте `--write`. Импорт использует `db.AddTasks`. Совпадение пары
`source_url + content_hash` обновляет ответ, решение и metadata.
Одинаковые условия под разными URL разделов могут остаться разными записями.

## Проверено

3 ноября 2026: браузерный сбор 1000 записей из 27 разделов; 971 запись номера 1
и 29 записей номера 2. Схема взята из ветки features/task-database.
Локальная PostgreSQL 16: запись, чтение, полная сверка JSON и повторный импорт.
Все 1000 записей содержали ответ и решение; ссылки на изображения — у 941.
Расхождений полей после чтения не найдено, повторный импорт сохранил количество,
ID и created_at. Различных условий по content_hash — 948.
Это проверка передачи данных, а не экспертиза правильности математических решений.

```powershell
python -m unittest discover -s pipelines/shkolkovo -p "test_*.py" -v
```

Браузерные тесты работают на синтетической странице и требуют установленный Edge.
Для Go: `gofmt`, `go test ./...`, `go vet ./...` из backend.

В Git не включаются выгрузки задач, HTML сеансов, локальные БД и пароли.
Материалы использовать с учётом условий источника. Перед расширением импорта
нужно проверить остальные номера, разметку, права на материалы и полноту пагинации.
